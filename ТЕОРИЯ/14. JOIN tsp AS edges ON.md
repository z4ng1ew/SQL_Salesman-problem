# 🔗 ЗАЧЕМ НУЖЕН JOIN И ЧТО ОН СОЕДИНЯЕТ?

---

## 🎯 ПРОСТОЙ ОТВЕТ

**JOIN нужен, чтобы найти ВСЕ ВОЗМОЖНЫЕ СЛЕДУЮЩИЕ ШАГИ из текущего города!**

```sql
JOIN tsp AS edges ON edges.point1 = routes.current_city
     │      │         │                      │
     │      │         │                      └─ Где мы СЕЙЧАС
     │      │         └──────────────────────── Откуда начинается ребро
     │      └────────────────────────────────── Алиас "рёбра"
     └───────────────────────────────────────── Таблица с дорогами
```

**Читается:** "Найди все дороги, которые начинаются в нашем текущем городе"

---

## 📖 ДЕТАЛЬНОЕ ОБЪЯСНЕНИЕ

### Что соединяем:

```
┌────────────────────────────────────────┐
│ Таблица 1: building_routes (routes)    │  ← Текущие маршруты
│ Содержит: где мы сейчас                │
└────────────────────────────────────────┘
                    +
┌────────────────────────────────────────┐
│ Таблица 2: tsp (edges)                 │  ← Все рёбра графа
│ Содержит: все возможные дороги         │
└────────────────────────────────────────┘
                    ↓
┌────────────────────────────────────────┐
│ Результат JOIN:                        │
│ Текущие маршруты + возможные шаги     │
└────────────────────────────────────────┘
```

## 🔍 КАКИЕ КОЛОНКИ СОЕДИНЯЕМ?

```sql
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     ↑                      ↑
                     │                      │
              "откуда ребро"          "где мы сейчас"
```

### Условие JOIN:

```
edges.point1 = routes.current_city

Означает:
"Начало ребра ДОЛЖНО СОВПАДАТЬ с текущим городом"
```

## 💡 НАГЛЯДНЫЙ ПРИМЕР

### Ситуация:

```
У нас есть маршрут: {a,b}
Мы сейчас в городе: 'b'
```

### Данные в routes (из building_routes):

```
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a,b}            │ b            │ 10               │
└──────────────────┴──────────────┴──────────────────┘
                       ↑
                  мы ЗДЕСЬ!
```

### Данные в edges (таблица tsp):

```
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   a     │   b     │  10  │
│   a     │   c     │  15  │
│   a     │   d     │  20  │
│   b     │   a     │  10  │ ← начинается в 'b' ✅
│   b     │   c     │  35  │ ← начинается в 'b' ✅
│   b     │   d     │  25  │ ← начинается в 'b' ✅
│   c     │   a     │  15  │
│   c     │   b     │  35  │
│   c     │   d     │  30  │
│   d     │   a     │  20  │
│   d     │   b     │  25  │
│   d     │   c     │  30  │
└─────────┴─────────┴──────┘
```

### JOIN выполняется так:

```sql
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     edges.point1 = 'b'

Условие: point1 = 'b'

Подходящие рёбра:
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │ ✅
│   b     │   c     │  35  │ ✅
│   b     │   d     │  25  │ ✅
└─────────┴─────────┴──────┘
```

### Результат JOIN:

```
┌──────────────────┬──────────────┬──────────────────┬─────────┬─────────┬──────┐
│ visited_cities   │ current_city │ accumulated_cost │ point1  │ point2  │ cost │
├──────────────────┼──────────────┼──────────────────┼─────────┼─────────┼──────┤
│ {a,b}            │ b            │ 10               │ b       │ a       │ 10   │
│ {a,b}            │ b            │ 10               │ b       │ c       │ 35   │
│ {a,b}            │ b            │ 10               │ b       │ d       │ 25   │
└──────────────────┴──────────────┴──────────────────┴─────────┴─────────┴──────┘
     ↑                                                             ↑        ↑
  откуда пришли                                            куда можем пойти
```

**3 строки = 3 варианта следующего шага!**

## 🎨 ВИЗУАЛИЗАЦИЯ

### Текущая ситуация:

```
Граф:
        a
       /|\
    10/ | \15
     /  |  \
    b   |20 c
     \  |  /
    25\ | /30
       \|/
        d

Мы сейчас в 'b':
visited = {a,b}
current = 'b'

Из 'b' можем пойти в:
• a (стоимость 10)
• c (стоимость 35)
• d (стоимость 25)
```

### JOIN находит эти варианты:

```
routes.current_city = 'b'
         ↓
    JOIN tsp
         ↓
WHERE point1 = 'b'
         ↓
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │ ← вариант 1
│   b     │   c     │  35  │ ← вариант 2
│   b     │   d     │  25  │ ← вариант 3
└─────────┴─────────┴──────┘
```

## 🔄 ПОЛНЫЙ ЦИКЛ РАБОТЫ JOIN

### Шаг 1: routes (откуда берём)

```
┌──────────────────┬──────────────┐
│ visited_cities   │ current_city │
├──────────────────┼──────────────┤
│ {a,b}            │ b            │
└──────────────────┴──────────────┘
```

### Шаг 2: edges (что ищем)

```
Все рёбра из таблицы tsp, где point1 = 'b':
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │
│   b     │   c     │  35  │
│   b     │   d     │  25  │
└─────────┴─────────┴──────┘
```

### Шаг 3: Результат JOIN (комбинация)

```
┌──────────────────┬──────────────┬─────────┬─────────┬──────┐
│ visited_cities   │ current_city │ point1  │ point2  │ cost │
├──────────────────┼──────────────┼─────────┼─────────┼──────┤
│ {a,b}            │ b            │ b       │ a       │ 10   │
│ {a,b}            │ b            │ b       │ c       │ 35   │
│ {a,b}            │ b            │ b       │ d       │ 25   │
└──────────────────┴──────────────┴─────────┴─────────┴──────┘
```

### Шаг 4: После WHERE (фильтрация)

```sql
WHERE NOT edges.point2 = ANY(routes.visited_cities)
      NOT 'a' IN {a,b} → FALSE ❌ убираем
      NOT 'c' IN {a,b} → TRUE  ✅ оставляем
      NOT 'd' IN {a,b} → TRUE  ✅ оставляем

Остаются:
┌──────────────────┬──────────────┬─────────┬─────────┬──────┐
│ visited_cities   │ current_city │ point1  │ point2  │ cost │
├──────────────────┼──────────────┼─────────┼─────────┼──────┤
│ {a,b}            │ b            │ b       │ c       │ 35   │
│ {a,b}            │ b            │ b       │ d       │ 25   │
└──────────────────┴──────────────┴─────────┴─────────┴──────┘
```

### Шаг 5: SELECT создаёт новые маршруты

```sql
SELECT
    routes.visited_cities || ARRAY[edges.point2]::varchar[],
    edges.point2,
    routes.accumulated_cost + edges.cost

Результат:
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a,b,c}          │ c            │ 45               │
│ {a,b,d}          │ d            │ 35               │
└──────────────────┴──────────────┴──────────────────┘
```

## 🎯 ЗАЧЕМ НУЖЕН JOIN?

### 1️⃣ Найти возможные следующие шаги

```
У нас:     current_city = 'b'
Нужно:     Куда можно пойти из 'b'?
Решение:   JOIN найдёт все рёбра из 'b'
```

### 2️⃣ Получить информацию о дорогах

```
JOIN даёт нам:
• point2 - следующий город (куда пойти)
• cost   - стоимость перехода
```

### 3️⃣ Соединить маршрут с графом

```
routes (маршруты) + tsp (граф) = возможные расширения маршрутов
```

---

## 💻 АНАЛОГИЯ В ПРОГРАММИРОВАНИИ

### В JavaScript:

```javascript
// routes - текущие маршруты
const routes = [
    {visited: ['a','b'], current: 'b', cost: 10}
];

// tsp - граф (все рёбра)
const tsp = [
    {point1: 'b', point2: 'a', cost: 10},
    {point1: 'b', point2: 'c', cost: 35},
    {point1: 'b', point2: 'd', cost: 25},
    // ...
];

// JOIN эквивалент:
const joined = [];
for (let route of routes) {
    for (let edge of tsp) {
        // ON edges.point1 = routes.current_city
        if (edge.point1 === route.current) {
            joined.push({
                ...route,         // из routes
                next: edge.point2, // из edges
                edgeCost: edge.cost // из edges
            });
        }
    }
}

// Результат:
// [
//   {visited: ['a','b'], current: 'b', cost: 10, next: 'a', edgeCost: 10},
//   {visited: ['a','b'], current: 'b', cost: 10, next: 'c', edgeCost: 35},
//   {visited: ['a','b'], current: 'b', cost: 10, next: 'd', edgeCost: 25}
// ]
```

## 📊 СРАВНИТЕЛЬНАЯ ТАБЛИЦА

| Аспект | routes | edges (tsp) | JOIN результат |
|--------|--------|-------------|----------------|
| **Что это** | Текущие маршруты | Все рёбра графа | Маршруты + возможные шаги |
| **Откуда** | building_routes | tsp (таблица) | Комбинация обеих |
| **Строк** | 1 (для {a,b}) | 12 (весь граф) | 3 (только из 'b') |
| **Информация** | Где мы сейчас | Все дороги | Куда можем пойти |

## 🔍 ДЕТАЛЬНЫЙ ПРИМЕР: ВСЕ ИТЕРАЦИИ

### Итерация 1:

```
routes:
┌──────────────────┬──────────────┐
│ visited_cities   │ current_city │
├──────────────────┼──────────────┤
│ {a}              │ a            │
└──────────────────┴──────────────┘

JOIN WHERE point1 = 'a':
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   a     │   b     │  10  │
│   a     │   c     │  15  │
│   a     │   d     │  20  │
└─────────┴─────────┴──────┘

→ 3 следующих шага: b, c, d
```

### Итерация 2:

```
routes (одна из строк):
┌──────────────────┬──────────────┐
│ visited_cities   │ current_city │
├──────────────────┼──────────────┤
│ {a,b}            │ b            │
└──────────────────┴──────────────┘

JOIN WHERE point1 = 'b':
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │ ← убрано WHERE (a уже посещена)
│   b     │   c     │  35  │ ✅
│   b     │   d     │  25  │ ✅
└─────────┴─────────┴──────┘

→ 2 следующих шага: c, d
```

## 🎓 КЛЮЧЕВЫЕ МОМЕНТЫ

### 1️⃣ JOIN соединяет ДВЕ таблицы

```
building_routes (маршруты) + tsp (граф)
```

### 2️⃣ Условие JOIN - совпадение городов

```sql
edges.point1 = routes.current_city

"Начало ребра = текущий город"
```

### 3️⃣ Результат - возможные следующие шаги

```
Из 1 строки routes может получиться несколько строк
(по количеству рёбер из текущего города)
```

### 4️⃣ БЕЗ JOIN невозможно найти следующий шаг

```
routes содержит только: где мы СЕЙЧАС
tsp содержит: куда можем ПОЙТИ

JOIN соединяет эту информацию!
```

## ✅ ПРОВЕРЬ СЕБЯ

### Вопрос 1: Что делает JOIN?

**Ответ:** Находит все рёбра, которые начинаются в текущем городе

---

### Вопрос 2: Какие таблицы соединяет?

**Ответ:** 
- `building_routes` (алиас routes) - текущие маршруты
- `tsp` (алиас edges) - все рёбра графа

---

### Вопрос 3: Какие колонки сравниваются в ON?

**Ответ:** 
- `edges.point1` (начало ребра)
- `routes.current_city` (где мы сейчас)

---

### Вопрос 4: Сколько строк получится, если current_city = 'b'?

**Ответ:** 3 строки (по количеству рёбер из 'b': b→a, b→c, b→d)

## 🏆 ИТОГОВАЯ СХЕМА

```
╔═══════════════════════════════════════════════╗
║ ЗАЧЕМ НУЖЕН JOIN                              ║
╠═══════════════════════════════════════════════╣
║                                               ║
║ routes (маршруты)        edges (граф)         ║
║ ┌─────────────────┐     ┌─────────────────┐   ║
║ │ visited: {a,b}  │     │ point1: b       │   ║
║ │ current: b      │ + + │ point2: c       │   ║
║ │ cost: 10        │     │ cost: 35        │   ║
║ └─────────────────┘     └─────────────────┘   ║
║         ↓                        ↓            ║
║         └────── JOIN ON ─────────┘            ║
║           edges.point1 = routes.current_city  ║
║                     ↓                         ║
║ ┌──────────────────────────────────────────┐  ║
║ │ Результат: маршрут + следующий шаг       │  ║
║ │ visited: {a,b}                           │  ║
║ │ current: b                               │  ║
║ │ next: c                                  │  ║
║ │ edgeCost: 35                             │  ║
║ └──────────────────────────────────────────┘  ║
║                                               ║
║ → Можем создать новый маршрут {a,b,c}         ║
╚═══════════════════════════════════════════════╝
```

---

**Кратко:** JOIN соединяет таблицу маршрутов (routes) с таблицей дорог (edges), чтобы найти все возможные следующие шаги из текущего города. Условие `edges.point1 = routes.current_city` означает "найди все дороги, которые начинаются там, где мы сейчас находимся". 🎯
