# 🔍 ДЕТАЛЬНЫЙ РАЗБОР `ARRAY[edges.point2]::varchar[]`

---

## 📖 РАЗБОР ПО ЧАСТЯМ

```sql
ARRAY[edges.point2]::varchar[]
  │      │     │      │   │
  │      │     │      │   └─── Тип: массив varchar
  │      │     │      └─────── Приведение типа
  │      │     └────────────── Одиночное значение (город)
  │      └──────────────────── Берём из таблицы edges
  └─────────────────────────── Оборачиваем в массив
```

---

## 🎯 ЧТО ЭТО ДЕЛАЕТ?

### Пошагово:

```sql
edges.point2           -- Шаг 1: Берём один город (например, 'b')
       │
       ↓
ARRAY[edges.point2]    -- Шаг 2: Заворачиваем в массив ['b']
       │
       ↓
::varchar[]            -- Шаг 3: Указываем тип "массив varchar"
```

---

## 🔢 ШАГ 1: `edges.point2` — Одиночное значение

### Что это:

```sql
edges.point2
  │      │
  │      └─── Колонка point2 (куда ведёт ребро)
  │
  └────────── Из таблицы edges (алиас для tsp)
```

### Примеры значений:

```sql
-- Когда edges указывает на ребро a→b:
edges.point2 = 'b'     ← одиночный символ

-- Когда edges указывает на ребро a→c:
edges.point2 = 'c'     ← одиночный символ

-- Когда edges указывает на ребро b→d:
edges.point2 = 'd'     ← одиночный символ
```

**Важно:** `edges.point2` — это НЕ массив! Это ОДНО значение типа CHAR(1).

---

## 📦 ШАГ 2: `ARRAY[edges.point2]` — Заворачивание в массив

### Что делает `ARRAY[...]`?

```sql
ARRAY[значение]
  │      │
  │      └─── Берёт значение
  │
  └────────── И создаёт массив с ОДНИМ элементом

Примеры:
ARRAY['b']     → {b}      (массив с одним элементом)
ARRAY[5]       → {5}      (массив с одним числом)
ARRAY['hello'] → {hello}  (массив с одной строкой)
```

### В нашем случае:

```sql
-- Если edges.point2 = 'b':
ARRAY[edges.point2]
ARRAY['b']           → {b}

-- Если edges.point2 = 'c':
ARRAY[edges.point2]
ARRAY['c']           → {c}

-- Если edges.point2 = 'd':
ARRAY[edges.point2]
ARRAY['d']           → {d}
```

---

## ❓ ЗАЧЕМ ЗАВОРАЧИВАТЬ В МАССИВ?

### Для операции конкатенации `||`!

```sql
routes.visited_cities || ARRAY[edges.point2]::varchar[]
        ↑                        ↑
     массив                   массив

Оператор || работает: массив + массив
```

### Почему не так:

```sql
-- ❌ НЕПРАВИЛЬНО:
routes.visited_cities || edges.point2
        ↑                    ↑
     массив             одиночное значение

PostgreSQL не знает, как склеить массив с одиночным значением!
```

### Правильно так:

```sql
-- ✅ ПРАВИЛЬНО:
routes.visited_cities || ARRAY[edges.point2]::varchar[]
        ↑                           ↓
     {a,b,c}                       {d}
        ↓                           ↓
              {a,b,c,d}  ← результат!
```

---

## 💡 НАГЛЯДНЫЕ ПРИМЕРЫ

### Пример 1: Добавление 'b' к {a}

```sql
-- Шаг 1: edges.point2 = 'b' (одиночное значение)
edges.point2
    ↓
   'b'

-- Шаг 2: Заворачиваем в массив
ARRAY[edges.point2]
ARRAY['b']
    ↓
   {b}

-- Шаг 3: Конкатенация
routes.visited_cities || ARRAY[edges.point2]::varchar[]
        {a}            ||        {b}
               ↓
            {a,b}
```

### Пример 2: Добавление 'c' к {a,b}

```sql
-- Текущее состояние
routes.visited_cities = {a,b}
edges.point2 = 'c'

-- Заворачиваем 'c' в массив
ARRAY['c'] = {c}

-- Конкатенация
{a,b} || {c} = {a,b,c}
```

### Пример 3: Добавление 'd' к {a,b,c}

```sql
-- Текущее состояние
routes.visited_cities = {a,b,c}
edges.point2 = 'd'

-- Заворачиваем 'd' в массив
ARRAY['d'] = {d}

-- Конкатенация
{a,b,c} || {d} = {a,b,c,d}
```

## 🔬 ДЕТАЛЬНЫЙ ПРИМЕР ИЗ КОДА

### Контекст:

```sql
SELECT
    routes.visited_cities || ARRAY[edges.point2]::varchar[],
    edges.point2,
    routes.accumulated_cost + edges.cost
FROM building_routes AS routes
JOIN tsp AS edges ON edges.point1 = routes.current_city
WHERE NOT edges.point2 = ANY(routes.visited_cities)
```

### Что происходит на итерации 1:

```
1. routes.visited_cities = {a}
   routes.current_city = 'a'

2. JOIN находит рёбра из 'a':
   edges: {point1: 'a', point2: 'b', cost: 10}

3. edges.point2 = 'b' (ОДИНОЧНОЕ значение!)

4. ARRAY[edges.point2] = ARRAY['b'] = {b}

5. Конкатенация:
   {a} || {b} = {a,b}

6. Новая строка:
   visited_cities = {a,b}
   current_city = 'b'
   accumulated_cost = 10
```

---

## 🎨 ВИЗУАЛИЗАЦИЯ

```
edges.point2 = 'b'
     ↓
    'b'  ← ЭТО ОДИНОЧНЫЙ СИМВОЛ (CHAR(1))
     ↓
ARRAY['b']  ← ЗАВОРАЧИВАЕМ В МАССИВ
     ↓
    {b}  ← ТЕПЕРЬ ЭТО МАССИВ С ОДНИМ ЭЛЕМЕНТОМ
     ↓
{a} || {b}  ← СКЛЕИВАЕМ ДВА МАССИВА
     ↓
   {a,b}  ← РЕЗУЛЬТАТ: РАСШИРЕННЫЙ МАССИВ
```

## 🔄 АЛЬТЕРНАТИВНЫЕ СПОСОБЫ (НЕ ИСПОЛЬЗУЮТСЯ)

### Способ 1: array_append (тоже работает)

```sql
-- Вместо:
routes.visited_cities || ARRAY[edges.point2]::varchar[]

-- Можно:
array_append(routes.visited_cities, edges.point2)

-- Результат одинаковый:
array_append({a,b}, 'c') → {a,b,c}
```

### Способ 2: Конкатенация с одиночным значением (работает в PostgreSQL)

```sql
-- В PostgreSQL можно так:
routes.visited_cities || edges.point2

-- PostgreSQL автоматически преобразует 'b' в {b}
-- Но ARRAY[...] более явно и понятно!
```

### Почему используем ARRAY[...]:

```
✅ Явная типизация
✅ Понятно, что происходит
✅ Работает везде одинаково
✅ Легче читать код
```

## 🧪 ИНТЕРАКТИВНЫЕ ПРИМЕРЫ

```sql
-- Попробуй в PostgreSQL:

-- Пример 1: Создание одноэлементного массива
SELECT ARRAY['b']::varchar[] AS single_element;
-- Результат: {b}

-- Пример 2: Конкатенация массивов
SELECT 
    ARRAY['a']::varchar[] AS массив1,
    ARRAY['b']::varchar[] AS массив2,
    ARRAY['a']::varchar[] || ARRAY['b']::varchar[] AS результат;
-- Результат:
--  массив1 | массив2 | результат
-- ---------+---------+-----------
--  {a}     | {b}     | {a,b}

-- Пример 3: Пошаговое добавление
WITH step1 AS (
    SELECT ARRAY['a']::varchar[] AS path
),
step2 AS (
    SELECT path || ARRAY['b']::varchar[] AS path FROM step1
),
step3 AS (
    SELECT path || ARRAY['c']::varchar[] AS path FROM step2
)
SELECT * FROM step1
UNION ALL SELECT * FROM step2
UNION ALL SELECT * FROM step3;
-- Результат:
--  path
-- --------
--  {a}
--  {a,b}
--  {a,b,c}

-- Пример 4: Из переменной
SELECT 
    'b'::CHAR(1) AS одиночное_значение,
    ARRAY['b'::CHAR(1)]::varchar[] AS в_массиве,
    ARRAY['a']::varchar[] || ARRAY['b'::CHAR(1)]::varchar[] AS склейка;
-- Результат:
--  одиночное_значение | в_массиве | склейка
-- --------------------+-----------+---------
--  b                  | {b}       | {a,b}
```

| Выражение | Тип | Значение | Описание |
|-----------|-----|----------|----------|

## 🎯 КЛЮЧЕВЫЕ МОМЕНТЫ

### 1️⃣ `edges.point2` — это ОДНО значение

```sql
edges.point2 = 'b'  ← НЕ массив!
```

### 2️⃣ `ARRAY[...]` заворачивает в массив

```sql
ARRAY['b'] = {b}  ← МАССИВ с одним элементом
```

### 3️⃣ Нужно для конкатенации с `||`

```sql
{a} || {b} = {a,b}  ← Массив + Массив
```

### 4️⃣ `::varchar[]` — явная типизация

```sql
ARRAY[edges.point2]::varchar[]  ← Говорим PostgreSQL: "это массив varchar"
```

### Вопрос 1: Что такое `edges.point2`?

**Ответ:** Одиночное значение типа CHAR(1) (один город)

---

### Вопрос 2: Что делает `ARRAY[edges.point2]`?

**Ответ:** Заворачивает одиночное значение в массив с одним элементом

---

### Вопрос 3: Зачем заворачивать в массив?

**Ответ:** Для конкатенации с оператором || (массив + массив)

### Вопрос 4: Чему равно `ARRAY['b']`?

**Ответ:** `{b}` (массив с одним элементом)

## 📝 ПРОСТОЕ ОБЪЯСНЕНИЕ

```
edges.point2 = 'b'        ← У нас есть город 'b'
ARRAY['b'] = {b}          ← Кладём его в коробку (массив)
{a} || {b} = {a,b}        ← Склеиваем две коробки

Зачем коробка?
Потому что оператор || работает только: коробка + коробка
Нельзя склеить: коробка + отдельный предмет
```

---

**Теперь ты полностью понимаешь, как "новый город заворачивается в массив"!** 🎯

**Кратко:** `edges.point2` — это один город ('b'), `ARRAY[edges.point2]` заворачивает его в массив ({b}), чтобы можно было склеить с другим массивом оператором ||.

## ✅ ДА, "edges" = "рёбра" (мн. число от "ребро")

```
edge = ребро (единственное число)
edges = рёбра (множественное число)
```

---

## 🔑 `edges` — ЭТО НЕ ОТДЕЛЬНАЯ ТАБЛИЦА!

### Это АЛИАС (псевдоним) для таблицы `tsp`!

```sql
JOIN tsp AS edges
     │      │
     │      └─── Псевдоним "edges" (рёбра)
     │
     └────────── Настоящая таблица "tsp"

Теперь можем писать:
edges.point1  вместо  tsp.point1
edges.point2  вместо  tsp.point2
edges.cost    вместо  tsp.cost
```

## 📖 ПОЛНОЕ ОБЪЯСНЕНИЕ

### В нашем коде:

```sql
SELECT
    routes.visited_cities || ARRAY[edges.point2]::varchar[],
    edges.point2,
    routes.accumulated_cost + edges.cost
FROM building_routes AS routes
JOIN tsp AS edges ON edges.point1 = routes.current_city
     │      │
     │      └─── Алиас "edges" (даём имя "рёбра")
     │
     └────────── Таблица "tsp" (настоящее имя)
```

### Что происходит:

```
1. У нас есть таблица tsp (настоящая таблица)

2. Мы даём ей короткое имя "edges" для этого запроса:
   FROM tsp AS edges

3. Теперь "edges" = "tsp" (один и тот же объект!)

4. Используем имя "edges" для ясности:
   edges.point1, edges.point2, edges.cost
```

## 💡 ЗАЧЕМ НАЗЫВАЕМ "edges" (рёбра)?

### Семантическая роль в запросе:

```
tsp = название таблицы (Traveling Salesman Problem)
     "что это такое"

edges = роль в запросе (рёбра графа)
       "как мы это используем"
```

### В нашем коде:

```sql
FROM building_routes AS routes
     │                  │
     таблица            роль: "маршруты"

JOIN tsp AS edges
     │      │
     таблица  роль: "рёбра графа"
```

### Почему "edges" понятнее:

```sql
-- С алиасом (ПОНЯТНО):
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     ↑
              "ребро начинается в текущем городе"

-- Без алиаса (менее понятно):
JOIN tsp ON tsp.point1 = routes.current_city
            ↑
         "что такое tsp.point1?" (не сразу ясно)
```

## 🔍 ДВА ИСПОЛЬЗОВАНИЯ ТАБЛИЦЫ `tsp`

### В нашем коде таблица `tsp` используется ДВАЖДЫ с разными алиасами:

```sql
-- ИСПОЛЬЗОВАНИЕ 1: В рекурсивной части
JOIN tsp AS edges
     │      │
     │      └─── Алиас "edges" (рёбра для продвижения)
     │
     └────────── Настоящая таблица

-- ИСПОЛЬЗОВАНИЕ 2: В complete_cycles
JOIN tsp AS return_edge
     │      │
     │      └─── Алиас "return_edge" (ребро возврата)
     │
     └────────── Та же таблица!
```

### Одна таблица, разные роли:

```
tsp (настоящая таблица)
│
├─ edges (алиас) → для поиска следующего города
│
└─ return_edge (алиас) → для возврата в 'a'
```

## 📋 ВСЕ АЛИАСЫ В КОДЕ

```sql
WITH RECURSIVE building_routes AS (
    ...
    FROM building_routes AS routes  ← Алиас "routes"
    JOIN tsp AS edges              ← Алиас "edges"
         │      │
         │      └─── Псевдоним
         │
         └────────── Настоящая таблица
),

complete_cycles AS (
    ...
    FROM building_routes AS routes  ← Алиас "routes" (снова)
    JOIN tsp AS return_edge        ← Алиас "return_edge"
         │      │
         │      └─── Другой псевдоним
         │
         └────────── Та же таблица tsp!
)
```

### Таблица алиасов:

| Настоящее имя | Алиас | Где используется | Зачем |
|---------------|-------|------------------|-------|
| `building_routes` | `routes` | Рекурсивная часть | Короче писать |
| `tsp` | `edges` | Рекурсивная часть | Подчёркивает роль "рёбра" |
| `building_routes` | `routes` | complete_cycles | Короче писать |
| `tsp` | `return_edge` | complete_cycles | Подчёркивает роль "возврат" |

```sql
Одна таблица, разные имена в разных частях запроса!
```

---

## 💻 ПРИМЕРЫ БЕЗ АЛИАСА

### Можно писать без алиаса:

```sql
-- Без алиаса (длинно и непонятно):
FROM building_routes
JOIN tsp ON tsp.point1 = building_routes.current_city
WHERE NOT tsp.point2 = ANY(building_routes.visited_cities)

-- С алиасами (коротко и понятно):
FROM building_routes AS routes
JOIN tsp AS edges ON edges.point1 = routes.current_city
WHERE NOT edges.point2 = ANY(routes.visited_cities)
```

## 🔬 ДОКАЗАТЕЛЬСТВО, ЧТО ЭТО ОДНА ТАБЛИЦА

### Проверим в PostgreSQL:

```sql
-- Создадим таблицу
CREATE TABLE tsp (
    point1 CHAR(1),
    point2 CHAR(1),
    cost INT
);

INSERT INTO tsp VALUES ('a', 'b', 10);

-- Используем БЕЗ алиаса:
SELECT point1, point2, cost FROM tsp;
-- Результат:
--  point1 | point2 | cost
-- --------+--------+------
--  a      | b      | 10

-- Используем С алиасом "edges":
SELECT edges.point1, edges.point2, edges.cost 
FROM tsp AS edges;
-- Результат:
--  point1 | point2 | cost
-- --------+--------+------
--  a      | b      | 10

-- ОДИНАКОВЫЙ РЕЗУЛЬТАТ! Это одна и та же таблица!
```

## 📊 СРАВНИТЕЛЬНАЯ ТАБЛИЦА

| Аспект | `tsp` | `edges` |
|--------|-------|---------|
| Что это | Настоящая таблица | Алиас (псевдоним) |
| Где существует | В базе данных | Только в запросе |
| Создаётся | CREATE TABLE | AS edges |
| Данные | Физически хранятся | Ссылается на tsp |
| Можно использовать | Везде | Только в текущем SELECT |

## 🎓 КЛЮЧЕВЫЕ МОМЕНТЫ

### 1️⃣ `edges` — НЕ отдельная таблица

```
edges = алиас для tsp
```

### 2️⃣ "edges" означает "рёбра"

```
edge = ребро
edges = рёбра (мн. число)
```

### 3️⃣ Создаётся так:

```sql
JOIN tsp AS edges
     │      │
     │      └─── Временное имя
     │
     └────────── Настоящая таблица
```

### 4️⃣ Зачем нужно:

```
✅ Короче писать (edges вместо tsp)
✅ Понятнее роль (edges = рёбра графа)
✅ Различать при множественном использовании
```
