# 🔧 Как создаются VIEW и MATERIALIZED VIEW?

## ✅ ДА! Оба через SELECT!

### 📺 **VIEW (виртуальная таблица)**

```sql
CREATE VIEW название_представления AS
SELECT колонки
FROM таблицы
WHERE условия;
```

**Конкретный пример:**

```sql
-- Создаём VIEW для женщин
CREATE VIEW v_females AS
SELECT id, name, age, address
FROM person
WHERE gender = 'female';

-- Теперь используем как обычную таблицу:
SELECT * FROM v_females;
```

**Что происходит внутри?**

```
Пользователь: SELECT * FROM v_females;
       ↓
PostgreSQL думает: "Ага, это VIEW!"
       ↓
Заменяет на: SELECT * FROM (
               SELECT id, name, age, address
               FROM person
               WHERE gender = 'female'
             );
       ↓
Выполняет запрос к РЕАЛЬНОЙ таблице person
       ↓
Возвращает результат
```

**На языке C/JS аналогия:**

```javascript
// VIEW - это как функция-обёртка:
function v_females() {
    return person.filter(p => p.gender === 'female');
}

// Каждый раз вызываешь - каждый раз пересчитывает!
console.log(v_females()); // Всегда свежие данные
```

---

### 📸 **MATERIALIZED VIEW (материализованное представление)**

```sql
CREATE MATERIALIZED VIEW название AS
SELECT колонки
FROM таблицы
WHERE условия;
```

**Конкретный пример:**

```sql
-- Создаём MATERIALIZED VIEW
CREATE MATERIALIZED VIEW mv_females AS
SELECT id, name, age, address
FROM person
WHERE gender = 'female';

-- Используем:
SELECT * FROM mv_females;

-- Обновляем данные:
REFRESH MATERIALIZED VIEW mv_females;
```

**Что происходит внутри?**

```
При CREATE MATERIALIZED VIEW:
       ↓
PostgreSQL выполняет SELECT прямо сейчас
       ↓
Сохраняет результат в ФИЗИЧЕСКУЮ таблицу на диске
       ↓
Эта таблица ЗАМОРАЖИВАЕТСЯ

При SELECT * FROM mv_females:
       ↓
PostgreSQL читает из ФИЗИЧЕСКОЙ таблицы
       ↓
НЕ обращается к исходной таблице person
       ↓
Быстро возвращает результат

При REFRESH:
       ↓
PostgreSQL заново выполняет SELECT
       ↓
Перезаписывает физическую таблицу
       ↓
Теперь данные свежие!
```

**На языке C/JS аналогия:**

```javascript
// MATERIALIZED VIEW - это как кэш:
let mv_females_cache = person.filter(p => p.gender === 'female');

// Используешь кэш (быстро, но может быть старым):
console.log(mv_females_cache);

// Обновляешь кэш вручную:
function refresh() {
    mv_females_cache = person.filter(p => p.gender === 'female');
}
```

## 📊 Сравнение синтаксиса

| Действие | VIEW | MATERIALIZED VIEW |
|----------|------|-------------------|
| **Создать** | `CREATE VIEW v AS SELECT...` | `CREATE MATERIALIZED VIEW mv AS SELECT...` |
| **Использовать** | `SELECT * FROM v` | `SELECT * FROM mv` |
| **Обновить** | Не нужно (всегда актуально) | `REFRESH MATERIALIZED VIEW mv` |
| **Удалить** | `DROP VIEW v` | `DROP MATERIALIZED VIEW mv` |
| **Изменить** | `CREATE OR REPLACE VIEW v AS...` | `DROP + CREATE` заново |

## 🏗️ Три уровня ANSI/SPARC — ПОДРОБНО

Представь базу данных как **многоэтажное здание**:

---

### 🎨 **1. EXTERNAL LEVEL (Внешний уровень)**
**= Что видят пользователи и приложения**

#### Что здесь находится?

- **VIEW (представления)**
- **Запросы пользователей**
- **Интерфейсы приложений**

#### Пример:

```sql
-- VIEW для бухгалтера (видит только суммы):
CREATE VIEW v_accountant AS
SELECT order_date, SUM(price) as total
FROM orders
GROUP BY order_date;

-- VIEW для продавца (видит детали):
CREATE VIEW v_salesman AS
SELECT customer_name, product, price, order_date
FROM orders
JOIN customers ON orders.customer_id = customers.id;
```

**Один и тот же человек в таблице, но:**
- 👔 Бухгалтер видит только цифры
- 🛍️ Продавец видит имена и товары

#### Аналогия с домом:

```
🚪 Входные двери в квартиры
- Квартира 1: Вход для семьи
- Квартира 2: Вход для гостей
- Квартира 3: Служебный вход

Все входят в ОДНО здание, но каждый через свою дверь!
```

#### На C/JS:

```c
// External Level - это как разные интерфейсы:
struct AccountantView {
    char date[11];
    int total;
};

struct SalesmanView {
    char customer[50];
    char product[50];
    int price;
};

// Один и тот же ORDER, но разные "взгляды"!
```

---

### 🧩 **2. CONCEPTUAL LEVEL (Концептуальный уровень)**
**= Логическая структура базы данных (схема)**

#### Что здесь находится?

- **Таблицы (TABLES)**
- **Связи между таблицами (Foreign Keys)**
- **Ограничения (Constraints)**
- **Правила (Rules)**

#### Пример:

```sql
-- Таблица person
CREATE TABLE person (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50),
    age INTEGER CHECK (age > 0),  -- правило
    gender VARCHAR(10)
);

-- Таблица orders
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    person_id BIGINT REFERENCES person(id),  -- связь
    price NUMERIC CHECK (price >= 0)  -- правило
);
```

**Это "чертёж" базы данных:**
- Какие таблицы есть
- Как они связаны
- Какие правила должны соблюдаться

#### Аналогия с домом:

```
📐 Архитектурный план здания
- 3 комнаты
- Кухня соединена с гостиной
- Спальня изолирована
- Окна выходят на юг
```

#### На C/JS:

```c
// Conceptual Level - это как структуры данных:
struct Person {
    int id;           // первичный ключ
    char name[50];
    int age;
};

struct Order {
    int id;
    int person_id;    // внешний ключ -> Person.id
    float price;
};
```

---

### 💾 **3. INTERNAL LEVEL (Внутренний уровень)**
**= Физическое хранение на диске**

#### Что здесь находится?

- **Файлы на диске**
- **Индексы (Indexes)**
- **Способы хранения (Storage)**
- **Оптимизация**

#### Пример:

```sql
-- Создаём индекс для ускорения поиска:
CREATE INDEX idx_person_name ON person(name);

-- PostgreSQL решает САМ:
-- - В каком файле хранить данные
-- - Как сжимать данные
-- - Как располагать на диске
```

**Пользователь НЕ видит:**
- Где физически лежит файл `/var/lib/postgresql/data/base/16384/12345`
- Как работает B-tree индекс
- Как данные сжаты

#### Аналогия с домом:

```
🔧 Фундамент, трубы, проводка
- Водопровод: трубы в стенах
- Электричество: провода под полом
- Канализация: трубы в подвале

Жильцы не видят, но всё работает благодаря этому!
```

#### На C/JS:

```c
// Internal Level - это как память и диск:

// Концептуально:
struct Person {
    int id;
    char name[50];
};

// Физически в памяти:
// Адрес 0x1000: [4 байта id][50 байт name][2 байта padding]
// Адрес 0x1038: следующая структура...

// На диске:
// Блок 1: данные person
// Блок 2: индекс по name
// Блок 3: продолжение данных
```

## 🎯 Как три уровня работают ВМЕСТЕ?

### Пример запроса:

```sql
SELECT * FROM v_females WHERE age > 25;
```

### Путь запроса через уровни:

```
👤 ПОЛЬЗОВАТЕЛЬ
       ↓
🎨 EXTERNAL LEVEL (уровень 1)
   "Ага, v_females - это VIEW"
   Разворачиваем VIEW в реальный запрос:
   SELECT * FROM person WHERE gender='female' AND age>25
       ↓
🧩 CONCEPTUAL LEVEL (уровень 2)
   "Проверяем схему:"
   - Таблица person существует? ✅
   - Колонка gender есть? ✅
   - Колонка age есть? ✅
   - Правила не нарушены? ✅
       ↓
💾 INTERNAL LEVEL (уровень 3)
   "Читаем с диска:"
   - Ищем файл таблицы person
   - Используем индекс по gender (если есть)
   - Читаем блоки данных
   - Фильтруем по age > 25
       ↓
   Возвращаем данные обратно вверх
       ↓
👤 ПОЛЬЗОВАТЕЛЬ получает результат
```

## 📦 Где хранится VIEW и MATERIALIZED VIEW?

### VIEW (виртуальная):

```
🎨 External Level:  VIEW определение (SQL-текст)
🧩 Conceptual:      Ничего не хранится
💾 Internal:        Ничего не хранится

Хранится только ОПРЕДЕЛЕНИЕ:
CREATE VIEW v_females AS SELECT...
```

**Файл:** только текст SQL в системной таблице `pg_views`

### MATERIALIZED VIEW:

```
🎨 External Level:  MVIEW определение (SQL-текст)
🧩 Conceptual:      MVIEW как "псевдо-таблица"
💾 Internal:        РЕАЛЬНЫЕ ДАННЫЕ на диске!

Хранится:
1. Определение: CREATE MATERIALIZED VIEW...
2. ФИЗИЧЕСКАЯ ТАБЛИЦА с данными!
```

**Файл:** текст SQL + реальный файл с данными (как обычная таблица)

## 🧠 Итоговое резюме

| Вопрос | Ответ |
|--------|-------|
| **Как создать VIEW?** | `CREATE VIEW v AS SELECT...` |
| **Как создать MVIEW?** | `CREATE MATERIALIZED VIEW mv AS SELECT...` |
| **External Level** | VIEW, запросы пользователей, интерфейсы |
| **Conceptual Level** | Таблицы, связи, правила (схема БД) |
| **Internal Level** | Файлы, индексы, физическое хранение |

### Запомни:

```
VIEW = SELECT-запрос с именем (виртуально)
MATERIALIZED VIEW = SELECT-запрос + физическое хранение результата

Уровни = 3 этажа здания:
🎨 External = Двери квартир (что видят люди)
🧩 Conceptual = План здания (как устроено)
💾 Internal = Фундамент (как построено)
```

**В коде:**
```javascript
// VIEW = функция (вызывается каждый раз)
const view = () => data.filter(x => x.age > 18);

// MATERIALIZED VIEW = переменная (кэш)
let mview = data.filter(x => x.age > 18);
```
