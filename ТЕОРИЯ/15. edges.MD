# 🎯 ЧТО ХРАНИТСЯ В `edges.point2`?

---

## 📖 ПРОСТОЙ ОТВЕТ

**`edges.point2` = КУДА ведёт ребро (город-назначение)**

```sql
edges.point2
  │      │
  │      └─── Колонка point2 (конечная точка ребра)
  │
  └────────── Из таблицы edges (алиас для tsp)

Значение: следующий город (куда можно пойти)
```

---

## 🔍 ДЕТАЛЬНОЕ ОБЪЯСНЕНИЕ

### Структура таблицы tsp:

```sql
CREATE TABLE tsp (
    point1 CHAR(1),  -- ОТКУДА (начало ребра)
    point2 CHAR(1),  -- КУДА (конец ребра) ← ВОТ ЭТО!
    cost   INT       -- стоимость
);
```

### Примеры данных:

```
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
│ (откуда)│ (куда)  │      │
├─────────┼─────────┼──────┤
│   a     │   b     │  10  │ ← ребро a→b, point2='b'
│   b     │   a     │  10  │ ← ребро b→a, point2='a'
│   a     │   c     │  15  │ ← ребро a→c, point2='c'
│   c     │   a     │  15  │ ← ребро c→a, point2='a'
│   b     │   c     │  35  │ ← ребро b→c, point2='c'
│   b     │   d     │  25  │ ← ребро b→d, point2='d'
└─────────┴─────────┴──────┘
           ↑
    edges.point2 хранит ЭТО!
```

---

## 🎨 ВИЗУАЛИЗАЦИЯ

### Ребро графа:

```
point1 ────→ point2
(откуда)     (куда)

   a    ────→    b
(начало)      (конец)

edges.point1 = 'a'  ← где начинается ребро
edges.point2 = 'b'  ← где заканчивается ребро
edges.cost = 10     ← сколько стоит
```

### В графе:

```
        a
       /│\
    10/ │ \15
     /  │  \
    b   │20 c
     \  │  /
    25\ │ /30
       \|/
        d

Ребро a→b:
• point1 = 'a' (начало)
• point2 = 'b' (конец) ← edges.point2
• cost = 10
```

## 💡 КОНКРЕТНЫЙ ПРИМЕР

### Ситуация: мы в городе 'b'

```sql
-- Текущий маршрут:
routes.visited_cities = {a,b}
routes.current_city = 'b'

-- JOIN ищет рёбра из 'b':
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     edges.point1 = 'b'

-- Найденные рёбра:
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │ ← edges.point2 = 'a'
│   b     │   c     │  35  │ ← edges.point2 = 'c'
│   b     │   d     │  25  │ ← edges.point2 = 'd'
└─────────┴─────────┴──────┘

edges.point2 хранит возможные следующие города:
• 'a' (можем пойти в a)
• 'c' (можем пойти в c)
• 'd' (можем пойти в d)
```

## 🔍 КАК ИСПОЛЬЗУЕТСЯ В КОДЕ

### В SELECT:

```sql
SELECT
    routes.visited_cities || ARRAY[edges.point2]::varchar[],
    edges.point2,
    routes.accumulated_cost + edges.cost
    
    ↑
    edges.point2 используется:
    1. Для добавления в массив пути
    2. Как новый current_city
```

### Пошагово:

```sql
-- Текущее состояние:
routes.visited_cities = {a,b}
routes.current_city = 'b'
routes.accumulated_cost = 10

-- JOIN нашёл ребро:
edges.point1 = 'b'
edges.point2 = 'c'  ← СЛЕДУЮЩИЙ ГОРОД!
edges.cost = 35

-- SELECT создаёт новую строку:
новый visited_cities = {a,b} || {c} = {a,b,c}
новый current_city = edges.point2 = 'c'
новый accumulated_cost = 10 + 35 = 45
```

## 🎯 ТРИ ИСПОЛЬЗОВАНИЯ `edges.point2`

### 1️⃣ Добавление в путь

```sql
routes.visited_cities || ARRAY[edges.point2]::varchar[]
{a,b}                 || {c}
        ↓
     {a,b,c}
```

### 2️⃣ Новый current_city

```sql
SELECT
    ...,
    edges.point2,  ← становится новым current_city
    ...

Было: current_city = 'b'
Стало: current_city = edges.point2 = 'c'
```

### 3️⃣ Проверка в WHERE

```sql
WHERE NOT edges.point2 = ANY(routes.visited_cities)
          ↑
    Проверяем: не посещали ли этот город раньше?
    
Если edges.point2 = 'c' и visited_cities = {a,b}:
→ NOT 'c' = ANY({a,b})
→ NOT (false)
→ true ✅ можно идти!
```

```javascript

```


# 🎯 ЧТО ХРАНИТСЯ В `edges.point1`?

---

## 📖 ПРОСТОЙ ОТВЕТ

**`edges.point1` = ОТКУДА начинается ребро (город-начало)**

```sql
edges.point1
  │      │
  │      └─── Колонка point1 (начальная точка ребра)
  │
  └────────── Из таблицы edges (алиас для tsp)

Значение: текущий город (откуда начинается дорога)
```

---

## 🔍 СРАВНЕНИЕ point1 и point2

```sql
CREATE TABLE tsp (
    point1 CHAR(1),  -- ОТКУДА (начало ребра) ← ВОТ ЭТО!
    point2 CHAR(1),  -- КУДА (конец ребра)
    cost   INT       -- стоимость
);
```

### Визуально:

```
point1 ────→ point2
(откуда)     (куда)

   a    ────→    b
(начало)      (конец)

edges.point1 = 'a'  ← ГДЕ НАЧИНАЕТСЯ ребро
edges.point2 = 'b'  ← ГДЕ ЗАКАНЧИВАЕТСЯ ребро
edges.cost = 10     ← СКОЛЬКО СТОИТ
```

## 💡 КАК ИСПОЛЬЗУЕТСЯ В КОДЕ

### В условии JOIN:

```sql
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     ↑                      ↑
                     │                      │
              начало ребра          где мы сейчас

Читается: "Найди рёбра, которые НАЧИНАЮТСЯ там, где мы СЕЙЧАС"
```

### Пример:

```sql
-- Мы сейчас в городе 'b':
routes.current_city = 'b'

-- JOIN ищет рёбра, где point1 = 'b':
JOIN tsp AS edges ON edges.point1 = 'b'

-- Найдёт:
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   b     │   a     │  10  │ ← point1 = 'b' ✅
│   b     │   c     │  35  │ ← point1 = 'b' ✅
│   b     │   d     │  25  │ ← point1 = 'b' ✅
└─────────┴─────────┴──────┘

НЕ найдёт:
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
├─────────┼─────────┼──────┤
│   a     │   b     │  10  │ ← point1 = 'a' ❌
│   c     │   b     │  35  │ ← point1 = 'c' ❌
│   d     │   b     │  25  │ ← point1 = 'd' ❌
└─────────┴─────────┴──────┘
```

## 💻 АНАЛОГИЯ В ПРОГРАММИРОВАНИИ

### В JavaScript:

```javascript
// Таблица tsp:
const tsp = [
    {point1: 'a', point2: 'b', cost: 10},
```

```c
char currentCity = 'b';

// Ищем рёбра, где point1 = currentCity
for (int i = 0; i < 3; i++) {
    if (edges[i].point1 == currentCity) {
        printf("Можем пойти в: %c\n", edges[i].point2);
    }
}
// Вывод:
// Можем пойти в: c
// Можем пойти в: d
```

## 🔄 ДВА ИСПОЛЬЗОВАНИЯ В КОДЕ

### 1️⃣ В JOIN (фильтрация рёбер):

```sql
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     ↑
            Условие: "начало ребра = текущий город"

Пример:
current_city = 'b'
→ Найдёт только рёбра, где point1 = 'b'
→ Результат: b→a, b→c, b→d
```

### 2️⃣ В complete_cycles (ребро возврата):

```sql
JOIN tsp AS return_edge 
  ON return_edge.point1 = routes.current_city 
 AND return_edge.point2 = 'a'
     ↑
"Ребро должно начинаться в текущем городе
 И заканчиваться в 'a'"

Пример:
current_city = 'c'
→ Ищем: point1='c' AND point2='a'
→ Находим: c→a (стоимость 15)
```

**Кратко:** 

**`edges.point1`** = **ОТКУДА** (начало ребра, текущий город)  
**`edges.point2`** = **КУДА** (конец ребра, следующий город)

Для ребра b→c:
- `edges.point1 = 'b'` (начинается в 'b')
- `edges.point2 = 'c'` (заканчивается в 'c')

**JOIN использует point1** для фильтрации: "Покажи рёбра, начинающиеся там, где я сейчас нахожусь" 🎯
