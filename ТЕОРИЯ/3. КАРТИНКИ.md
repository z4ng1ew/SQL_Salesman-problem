# Анализ изображений из проекта SQL

## 🖼️ Изображение 1: D04_03.png - **VIEW (Обычное представление)**

### Что показано на графике:

**Оси координат:**
- 📈 **Data State** (вертикальная ось) — состояние данных в таблицах
- ⏱️ **Time Line** (горизонтальная ось) — временная шкала

**Элементы:**
- 🟡 **Желтые точки** (quantum #1-4) — моменты времени запросов к VIEW
- 🟢 **Зеленые точки** — актуальное состояние данных в таблицах
- 🟠 **Оранжевая пунктирная линия** — траектория изменения данных в базовых таблицах
- 💚 **Зеленые области "View Data"** — данные, которые возвращает VIEW

### 🔑 Ключевой принцип:

**VIEW всегда показывает АКТУАЛЬНЫЕ данные!**

Когда вы делаете запрос к VIEW в любой момент времени (quantum #1, #2, #3 или #4), вы получаете:
- ✅ Текущее состояние базовых таблиц
- ✅ Все последние изменения
- ✅ "Живые" данные без задержки

### 🍕 Аналогия из жизни:

**VIEW = Витрина пиццерии**
- Вы смотрите через стекло на кухню
- Видите, какие пиццы **прямо сейчас** готовы
- Если повар добавил новую пиццу — вы сразу её видите
- Если убрал — вы сразу это замечаете

## 🖼️ Изображение 2: D04_04.png - **MATERIALIZED VIEW**

### Что показано:

**Новые элементы:**
- 🔵 **Пустые голубые кружки** — состояние данных в Materialized View
- 🟢 **Зеленая ломаная линия** — траектория MView (отстаёт от реальных данных)
- 💙 **Голубые области "MView Data"** — данные, которые возвращает MView

### 🔑 Ключевой принцип:

**MATERIALIZED VIEW показывает УСТАРЕВШИЕ данные!**

Посмотрите на график:
- В **quantum #2**: MView показывает данные из quantum #1 (🔵 отстаёт от 🟢)
- В **quantum #3**: MView показывает данные из quantum #2
- В **quantum #4**: MView показывает данные из quantum #3

**MView обновляется только при команде REFRESH!**

### 🍕 Аналогия из жизни:

**MATERIALIZED VIEW = Фотография меню**
- Вы сделали фото меню утром
- Днём в пиццерии добавили новые позиции
- Но на **вашей фотографии** всё ещё старое меню!
- Чтобы увидеть изменения — нужно сделать **новое фото** (REFRESH)

### ⚡ Когда это полезно?

**Плюсы MView:**
- 🚀 **Быстрее** — данные уже готовы, не нужно пересчитывать
- 💾 **Можно создать индексы** — ещё больше ускорить

**Минусы MView:**
- 🐌 **Не актуально** — данные с задержкой
- 📦 **Занимает место** — хранится физически

## 🖼️ Изображение 3: schema.png - **Схема БД пиццерий**

### 🏗️ Структура базы данных:

```
         pizzeria (пиццерии)
         ┌─────────────┐
         │ id          │ 🔑 Первичный ключ
         │ name        │ 📝 Название
         │ rating      │ ⭐ Рейтинг
         └──────┬──────┘
                │
        ┌───────┴───────┐
        │               │
    ┌───▼────┐      ┌───▼──────┐
    │ menu   │      │ person_  │
    │        │      │ visits   │
    └───┬────┘      └───┬──────┘
        │               │
        │           ┌───▼──────┐
        │           │ person   │
        │           └───┬──────┘
        │               │
    ┌───▼───────────────▼┐
    │ person_order       │
    └────────────────────┘
```

### 📊 Таблицы:

#### 1️⃣ **pizzeria** (Пиццерии)
```
🔑 id       - уникальный номер
📛 name     - "Domino's", "Pizza Hut"
⭐ rating   - 4.5, 3.2, ...
```

#### 2️⃣ **person** (Клиенты)
```
🔑 id       - уникальный номер
👤 name     - "Дмитрий", "Анна"
🎂 age      - 25, 30, ...
⚥ gender    - "male", "female"
🏠 address  - "ул. Ленина, 10"
```

#### 3️⃣ **menu** (Меню)
```
🔑 id           - уникальный номер
🔗 pizzeria_id  - какая пиццерия
🍕 pizza_name   - "Маргарита", "Пепперони"
💰 price        - 800, 1200, ...
```

#### 4️⃣ **person_visits** (Посещения)
```
🔑 id           - уникальный номер
👤 person_id    - кто посетил
🏪 pizzeria_id  - куда пришёл
📅 visit_date   - 2022-01-08
```

#### 5️⃣ **person_order** (Заказы)
```
🔑 id          - уникальный номер
👤 person_id   - кто заказал
🍕 menu_id     - что заказал
📅 order_date  - 2022-01-08
```

### 🔗 Связи между таблицами:

```
person ──┬──> person_visits ──> pizzeria
         │                         ↑
         └──> person_order ──> menu ─┘
```

**Читается так:**
- Человек **посещает** пиццерию (person → person_visits → pizzeria)
- Человек **заказывает** пиццу из меню (person → person_order → menu → pizzeria)

### 🎯 Важная деталь:

**Посещение ≠ Заказ!**

Примеры:
- 🚶 Человек **зашёл** в пиццерию, посмотрел меню, ушёл → есть **visit**, нет **order**
- 📱 Человек дома **заказал** доставку по телефону → есть **order**, нет **visit**
- 🍕 Человек пришёл и заказал на месте → есть и **visit**, и **order**

## 💡 Итоговое сравнение

| Аспект | VIEW | MATERIALIZED VIEW |
|--------|------|-------------------|
| **График** | Зелёная область всегда на линии таблиц | Голубая область отстаёт |
| **Актуальность** | ✅ Всегда свежие данные | ⚠️ Устаревшие до REFRESH |
| **Скорость** | 🐌 Медленнее | 🚀 Быстрее |
| **Место на диске** | Не занимает | Занимает |
| **Аналогия** | Витрина магазина | Фотография витрины |

**Когда использовать?**
- **VIEW** → если нужна актуальность (онлайн-системы)
- **MATERIALIZED VIEW** → если нужна скорость и данные меняются редко (отчёты, аналитика)
