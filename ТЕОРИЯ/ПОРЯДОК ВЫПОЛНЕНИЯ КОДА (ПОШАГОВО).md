# 🎬 ПОРЯДОК ВЫПОЛНЕНИЯ КОДА (ПОШАГОВО)

---

## 📋 ОБЩАЯ СХЕМА ВЫПОЛНЕНИЯ

```
1. DROP TABLE          ← Удаление старой таблицы
2. CREATE TABLE        ← Создание структуры
3. INSERT              ← Заполнение данными
4. WITH RECURSIVE      ← Рекурсивное построение маршрутов
   ├─ Anchor member    ← Базовый случай (1 раз)
   ├─ Recursive member ← Рекурсивный шаг (многократно)
   └─ Результат        → building_routes
5. complete_cycles     ← Формирование гамильтоновых циклов
6. SELECT              ← Фильтрация и вывод результата
```

---

## 🎯 ДЕТАЛЬНЫЙ ПОРЯДОК ВЫПОЛНЕНИЯ

---

### 📍 ШАГ 1: DROP TABLE

```sql
DROP TABLE IF EXISTS tsp CASCADE;
```

**Что происходит:**
```
1. PostgreSQL проверяет: "Есть ли таблица tsp?"
   ├─ Если ДА → удаляет таблицу + все зависимости (CASCADE)
   └─ Если НЕТ → ничего не делает (IF EXISTS)

2. Результат: таблица tsp удалена (или не существовала)
```

**Зачем:**
- Гарантия чистого старта
- Можно запускать скрипт многократно
- Нет ошибок "таблица уже существует"

---

### 📍 ШАГ 2: CREATE TABLE

```sql
CREATE TABLE tsp (
    point1 CHAR(1),
    point2 CHAR(1),
    cost   INT
);
```

**Что происходит:**
```
PostgreSQL создаёт новую таблицу tsp со структурой:
┌─────────┬─────────┬──────┐
│ point1  │ point2  │ cost │
│ CHAR(1) │ CHAR(1) │ INT  │
└─────────┴─────────┴──────┘
(пока пустая, 0 строк)
```

### 📍 ШАГ 4: WITH RECURSIVE building_routes

Это САМАЯ СЛОЖНАЯ часть! Разбираем пошагово.

---

#### 🔷 ШАГ 4.1: ANCHOR MEMBER (итерация 0)

```sql
SELECT
    ARRAY['a']::varchar[]  AS visited_cities,
    'a'::CHAR(1)           AS current_city,
    0                      AS accumulated_cost
```

**Что происходит:**
```
PostgreSQL создаёт начальную строку:

ИТЕРАЦИЯ 0 (anchor):
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a}              │ a            │ 0                │
└──────────────────┴──────────────┴──────────────────┘

Это "семя" рекурсии - начальное состояние
```

---

#### 🔷 ШАГ 4.2: RECURSIVE MEMBER (итерация 1)

```sql
SELECT
    routes.visited_cities || ARRAY[edges.point2]::varchar[],
    edges.point2,
    routes.accumulated_cost + edges.cost
FROM building_routes AS routes
JOIN tsp AS edges ON edges.point1 = routes.current_city
WHERE NOT edges.point2 = ANY(routes.visited_cities)
```

**Что происходит:**

```
1. Берём результат anchor member:
   routes: {visited_cities: {a}, current_city: 'a', cost: 0}

2. JOIN с таблицей tsp где point1 = 'a':
   ┌─────────┬─────────┬──────┐
   │ point1  │ point2  │ cost │
   ├─────────┼─────────┼──────┤
   │   a     │   b     │  10  │ ← подходит!
   │   a     │   c     │  15  │ ← подходит!
   │   a     │   d     │  20  │ ← подходит!
   └─────────┴─────────┴──────┘

3. Проверяем WHERE NOT ... = ANY:
   - 'b' не в {a}? ✅ Да
   - 'c' не в {a}? ✅ Да
   - 'd' не в {a}? ✅ Да

4. Создаём 3 новые строки:

ИТЕРАЦИЯ 1 (recursive):
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a,b}            │ b            │ 10               │
│ {a,c}            │ c            │ 15               │
│ {a,d}            │ d            │ 20               │
└──────────────────┴──────────────┴──────────────────┘
```

---

#### 🔷 ШАГ 4.3: RECURSIVE MEMBER (итерация 2)

**Что происходит:**

```
1. Берём результаты итерации 1 (3 строки)

2. Для каждой строки делаем JOIN и расширяем:

Из {a,b}:
  JOIN где point1 = 'b' и point2 не в {a,b}
  → Находим: b→c (35), b→d (25)
  → Создаём: {a,b,c}, {a,b,d}

Из {a,c}:
  JOIN где point1 = 'c' и point2 не в {a,c}
  → Находим: c→b (35), c→d (30)
  → Создаём: {a,c,b}, {a,c,d}

Из {a,d}:
  JOIN где point1 = 'd' и point2 не в {a,d}
  → Находим: d→b (25), d→c (30)
  → Создаём: {a,d,b}, {a,d,c}

ИТЕРАЦИЯ 2 (recursive):
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a,b,c}          │ c            │ 45               │
│ {a,b,d}          │ d            │ 35               │
│ {a,c,b}          │ b            │ 50               │
│ {a,c,d}          │ d            │ 45               │
│ {a,d,b}          │ b            │ 45               │
│ {a,d,c}          │ c            │ 50               │
└──────────────────┴──────────────┴──────────────────┘

6 строк (по 2 из каждой предыдущей)
```

---

#### 🔷 ШАГ 4.4: RECURSIVE MEMBER (итерация 3)

**Что происходит:**

```
1. Берём результаты итерации 2 (6 строк)

2. Для каждой строки добавляем последний город:

Из {a,b,c}:
  → Добавляем 'd': {a,b,c,d}

Из {a,b,d}:
  → Добавляем 'c': {a,b,d,c}

Из {a,c,b}:
  → Добавляем 'd': {a,c,b,d}

Из {a,c,d}:
  → Добавляем 'b': {a,c,d,b}

Из {a,d,b}:
  → Добавляем 'c': {a,d,b,c}

Из {a,d,c}:
  → Добавляем 'b': {a,d,c,b}

ИТЕРАЦИЯ 3 (recursive):
┌──────────────────┬──────────────┬──────────────────┐
│ visited_cities   │ current_city │ accumulated_cost │
├──────────────────┼──────────────┼──────────────────┤
│ {a,b,c,d}        │ d            │ 75               │
│ {a,b,d,c}        │ c            │ 65               │
│ {a,c,b,d}        │ d            │ 75               │
│ {a,c,d,b}        │ b            │ 70               │
│ {a,d,b,c}        │ c            │ 80               │
│ {a,d,c,b}        │ b            │ 85               │
└──────────────────┴──────────────┴──────────────────┘

6 строк (полные маршруты!)
```

#### 🔷 ШАГ 4.5: РЕКУРСИЯ ОСТАНАВЛИВАЕТСЯ

```
Пытаемся сделать итерацию 4:

Для {a,b,c,d}:
  WHERE NOT edges.point2 = ANY({a,b,c,d})

  → Нет подходящих рёбер
  → 0 новых строк

Рекурсия останавливается, т.к. нет новых строк.
```

### 📍 ШАГ 5: complete_cycles

```sql
complete_cycles AS (
    SELECT
        routes.accumulated_cost + return_edge.cost AS total_cost,
        '{' || array_to_string(routes.visited_cities || ARRAY['a']::varchar[], ',') || '}' AS tour
    FROM building_routes AS routes
    JOIN tsp AS return_edge 
      ON return_edge.point1 = routes.current_city 
     AND return_edge.point2 = 'a'
    WHERE array_length(routes.visited_cities, 1) = (
        SELECT COUNT(DISTINCT point1) FROM tsp
    )
)
```

**Что происходит:**

```
1. Из building_routes (16 строк) берём только полные маршруты:
   WHERE array_length(...) = 4
   → Остаются только последние 6 строк

2. Для каждой находим ребро возврата в 'a':
   JOIN tsp WHERE point1 = current_city AND point2 = 'a'

3. Вычисляем полную стоимость и форматируем вывод:

┌────────────┬────────────────┐
│ total_cost │ tour           │
├────────────┼────────────────┤
│ 95         │ {a,b,c,d,a}    │ ← 75 + 20 (d→a)
│ 80         │ {a,b,d,c,a}    │ ← 65 + 15 (c→a)
│ 95         │ {a,c,b,d,a}    │ ← 75 + 20 (d→a)
│ 80         │ {a,c,d,b,a}    │ ← 70 + 10 (b→a)
│ 95         │ {a,d,b,c,a}    │ ← 80 + 15 (c→a)
│ 95         │ {a,d,c,b,a}    │ ← 85 + 10 (b→a)
└────────────┴────────────────┘

6 гамильтоновых циклов
```

### 📍 ШАГ 6: ФИНАЛЬНЫЙ SELECT

```sql
SELECT total_cost, tour
FROM complete_cycles
WHERE total_cost = (SELECT MIN(total_cost) FROM complete_cycles)
ORDER BY total_cost, tour;
```

**Что происходит:**

```
1. Находим минимальную стоимость:
   SELECT MIN(total_cost) FROM complete_cycles
   → 80

2. Фильтруем только циклы со стоимостью 80:
   WHERE total_cost = 80

3. Сортируем:
   ORDER BY total_cost, tour

ФИНАЛЬНЫЙ РЕЗУЛЬТАТ:
┌────────────┬────────────────┐
│ total_cost │ tour           │
├────────────┼────────────────┤
│ 80         │ {a,b,d,c,a}    │
│ 80         │ {a,c,d,b,a}    │
└────────────┴────────────────┘

Это и есть ответ задачи!
```

## 🔄 ПОРЯДОК ВЫПОЛНЕНИЯ CTE

**Важно понять:**

```
WITH RECURSIVE building_routes AS (...),
complete_cycles AS (...)

PostgreSQL выполняет:
1. Сначала building_routes (полностью!)
2. Потом complete_cycles (используя результат #1)
3. Потом финальный SELECT (используя результат #2)

НЕ параллельно! Последовательно!
```

## 🎓 КЛЮЧЕВЫЕ МОМЕНТЫ

### 1️⃣ Рекурсия выполняется ИТЕРАТИВНО

```
НЕ так (одновременно):
❌ Anchor + Recursive + Recursive + ...

А так (по очереди):
✅ Anchor → Recursive(iter1) → Recursive(iter2) → ...
```

### 2️⃣ UNION ALL собирает ВСЕ итерации

```
Результат building_routes =
  anchor (iter 0) +
  recursive (iter 1) +
  recursive (iter 2) +
  recursive (iter 3)
```

### 3️⃣ Каждый CTE использует предыдущие

```
building_routes → complete_cycles → SELECT

Поток данных идёт слева направо →
```

## 💡 АНАЛОГИЯ С ПРОГРАММИРОВАНИЕМ

### В JavaScript:

```javascript
// 1-3: Подготовка данных
const tsp = [
  {point1: 'a', point2: 'b', cost: 10},
  // ...
];

// 4: Рекурсивное построение
let building_routes = [];

// Anchor
building_routes.push({visited: ['a'], current: 'a', cost: 0});

// Recursive (итерации)
let iteration = 1;
while (true) {
  const newRoutes = [];
  for (let route of building_routes) {
    for (let edge of tsp.filter(e => e.point1 === route.current)) {
      if (!route.visited.includes(edge.point2)) {
        newRoutes.push({
          visited: [...route.visited, edge.point2],
          current: edge.point2,
          cost: route.cost + edge.cost
        });
      }
    }
  }
  if (newRoutes.length === 0) break;
  building_routes.push(...newRoutes);
  iteration++;
}

// 5: complete_cycles
const complete_cycles = building_routes
  .filter(r => r.visited.length === 4)
  .map(r => ({
    cost: r.cost + getCost(r.current, 'a'),
    tour: `{${[...r.visited, 'a'].join(',')}}`
  }));

// 6: SELECT
const minCost = Math.min(...complete_cycles.map(c => c.cost));
const result = complete_cycles
  .filter(c => c.cost === minCost)
  .sort((a, b) => a.cost - b.cost || a.tour.localeCompare(b.tour));

console.log(result);
```
