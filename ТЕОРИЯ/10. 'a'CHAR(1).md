# 🔍 ДЕТАЛЬНЫЙ РАЗБОР `'a'::CHAR(1) AS current_city`

---

## 📖 РАЗБОР ПО ЧАСТЯМ

```sql
'a'::CHAR(1)  AS current_city
 │    │   │    │      │
 │    │   │    │      └─── Имя колонки (название)
 │    │   │    │
 │    │   │    └────────── Ключевое слово "назовём как"
 │    │   │
 │    │   └─────────────── Тип: символ фиксированной длины (1)
 │    │
 │    └───────────────────── Оператор приведения типа
 │
 └────────────────────────── Значение: строка 'a'
```

---

## 🎯 ЧТО ЭТО ДЕЛАЕТ?

### Пошагово:

```sql
'a'              -- Шаг 1: Строковый литерал (текстовое значение 'a')
  │
  ↓
::CHAR(1)        -- Шаг 2: Явно указываем тип "1 символ фиксированной длины"
  │
  ↓
AS current_city  -- Шаг 3: Даём этому значению имя "current_city"
```

---

## 🔤 ШАГ 1: `'a'` — Строковый литерал

### Что это:

```sql
'a'
 │
 └─── Одиночные кавычки означают "строка" в SQL
      Внутри кавычек символ 'a'
```

### Примеры строковых литералов:

```sql
'a'           → строка с одним символом
'hello'       → строка из 5 символов
'123'         → строка (не число!)
'Moscow'      → строка
''            → пустая строка
```

### Отличие от чисел:

```sql
'5'    → строка (текст)
5      → число

'100'  → строка
100    → число
```

---

## 🔄 ШАГ 2: `::CHAR(1)` — Приведение типа

### Что такое `::`?

```sql
::     ← Оператор CAST (приведение типа)

Синтаксис:
значение::тип

Читается: "преобразовать значение в тип"
```

### Что такое `CHAR(1)`?

```sql
CHAR(1)
 │    │
 │    └─── (1) = ровно 1 символ
 │
 └──────── CHAR = тип "символьная строка фиксированной длины"

Читается: "ровно один символ"
```

### Примеры приведения:

```sql
'a'::CHAR(1)      → символ 'a' типа CHAR(1)
'b'::CHAR(1)      → символ 'b' типа CHAR(1)
'hello'::CHAR(5)  → строка 'hello' типа CHAR(5)
'5'::INTEGER      → число 5 (строка → число)
```

### Зачем нужно приведение?

```sql
-- БЕЗ приведения (PostgreSQL угадывает тип):
'a'               → тип: text (общий текстовый тип)

-- С приведением (явно указываем):
'a'::CHAR(1)      → тип: CHAR(1) (ровно 1 символ)

Зачем:
✅ Явная типизация
✅ Совместимость с колонкой в таблице tsp (point1 CHAR(1))
✅ Консистентность кода
```

---

## 📛 ШАГ 3: `AS current_city` — Имя колонки

### Что это:

```sql
AS current_city
│      │
│      └─── Новое имя (алиас)
│
└────────── Ключевое слово "назовём как"

Результат: колонка будет называться "current_city"
```

### Зачем нужно:

```sql
-- БЕЗ AS (непонятное имя):
SELECT 'a'::CHAR(1);

-- Результат:
--  ?column?
-- ----------
--  a


-- С AS (понятное имя):
SELECT 'a'::CHAR(1) AS current_city;

-- Результат:
--  current_city
-- --------------
--  a
```

## 🆚 СРАВНЕНИЕ С ПРЕДЫДУЩЕЙ СТРОКОЙ

### Обе строки из anchor member:

```sql
SELECT
    ARRAY['a']::varchar[]  AS visited_cities,  ← МАССИВ
    'a'::CHAR(1)           AS current_city,    ← ОДНО ЗНАЧЕНИЕ
    0                      AS accumulated_cost
```

### Различия:

| Аспект | `ARRAY['a']::varchar[]` | `'a'::CHAR(1)` |
|--------|-------------------------|----------------|
| **Что это** | Массив | Одиночное значение |
| **Тип** | varchar[] (массив) | CHAR(1) (один символ) |
| **Значение** | {a} | a |
| **Используется для** | Хранение пути | Текущая позиция |

### Визуально:

```
ARRAY['a']::varchar[] AS visited_cities
           ↓
      {a}         ← это МАССИВ (может расти)
      
'a'::CHAR(1) AS current_city
    ↓
    a           ← это ОДИН СИМВОЛ (не меняется размер)
```

## 🔬 ДЕТАЛЬНЫЕ ПРИМЕРЫ

### Пример 1: Разные символы

```sql
SELECT 'a'::CHAR(1) AS city_a;
-- Результат: a

SELECT 'b'::CHAR(1) AS city_b;
-- Результат: b

SELECT 'Z'::CHAR(1) AS city_z;
-- Результат: Z
```

### Пример 2: Без приведения типа

```sql
-- PostgreSQL сам определит тип
SELECT 'a' AS current_city;
-- Тип будет: text (не CHAR(1))
```

### Пример 3: Разные способы приведения

```sql
-- Способ 1: :: (короткий)
SELECT 'a'::CHAR(1) AS city;

-- Способ 2: CAST (длинный)
SELECT CAST('a' AS CHAR(1)) AS city;

-- Оба дают одинаковый результат!
```

### Пример 4: Разные типы

```sql
SELECT 'a'::CHAR(1) AS char_type;
-- Тип: character(1)
-- Значение: a

SELECT 'a'::VARCHAR(1) AS varchar_type;
-- Тип: character varying(1)
-- Значение: a

SELECT 'a'::TEXT AS text_type;
-- Тип: text
-- Значение: a

-- Все хранят 'a', но РАЗНЫЕ типы!
```

## 🎯 ЗАЧЕМ ЭТО В НАШЕМ КОДЕ?

### В контексте рекурсии:

```sql
WITH RECURSIVE building_routes AS (
    -- ANCHOR MEMBER:
    SELECT
        ARRAY['a']::varchar[] AS visited_cities,  ← массив пути
        'a'::CHAR(1)          AS current_city,    ← текущее положение
        0                     AS accumulated_cost
    
    UNION ALL
    
    -- RECURSIVE MEMBER:
    SELECT
        routes.visited_cities || ARRAY[edges.point2]::varchar[],
        edges.point2,            ← новая текущая позиция
        ↑
        └── берём point2 из таблицы (тип CHAR(1))
```

### Что происходит:

```
ИТЕРАЦИЯ 0 (anchor):
visited_cities = {a}           ← где были
current_city = 'a'             ← где сейчас

ИТЕРАЦИЯ 1 (recursive):
visited_cities = {a,b}         ← где были
current_city = 'b'             ← где сейчас (переместились!)

ИТЕРАЦИЯ 2 (recursive):
visited_cities = {a,b,c}       ← где были
current_city = 'c'             ← где сейчас (переместились!)
```

## 🔑 ПОЧЕМУ ИМЕННО CHAR(1)?

### Совместимость с таблицей:

```sql
-- В таблице tsp:
CREATE TABLE tsp (
    point1 CHAR(1),  ← тип CHAR(1)
    point2 CHAR(1),  ← тип CHAR(1)
    cost   INT
);

-- В anchor member:
'a'::CHAR(1) AS current_city  ← тоже CHAR(1)

-- При JOIN:
JOIN tsp AS edges ON edges.point1 = routes.current_city
                     ↑                     ↑
                  CHAR(1)              CHAR(1)

→ Типы совпадают! JOIN работает эффективно!
```

## 🎓 АНАЛОГИЯ ДЛЯ ПОНИМАНИЯ

### Представь GPS-навигатор:

```javascript
// visited_cities = массив посещённых точек
const visited_cities = ['a', 'b', 'c'];  // где я уже был

// current_city = текущее местоположение
const current_city = 'c';  // где я СЕЙЧАС

// accumulated_cost = километраж
const accumulated_cost = 45;  // сколько проехал
```

### В SQL:

```sql
visited_cities: {a,b,c}  ← история маршрута (массив)
current_city: 'c'        ← текущая точка (одно значение)
accumulated_cost: 45     ← общий путь (число)
```

## 🔍 РАЗНИЦА: МАССИВ vs ОДИНОЧНОЕ ЗНАЧЕНИЕ

```sql
-- МАССИВ (можно добавлять элементы):
ARRAY['a']::varchar[]
        ↓
    {a}
        ↓ добавляем 'b'
    {a,b}
        ↓ добавляем 'c'
    {a,b,c}


-- ОДИНОЧНОЕ ЗНАЧЕНИЕ (заменяется полностью):
'a'::CHAR(1)
    ↓
    a
    ↓ заменяем на 'b'
    b
    ↓ заменяем на 'c'
    c
```

**Ответ:** Даёт колонке понятное имя "current_city"

## 📝 СРАВНЕНИЕ ВСЕХ ТРЁХ КОЛОНОК ANCHOR MEMBER

```sql
SELECT
    ARRAY['a']::varchar[]  AS visited_cities,  ← МАССИВ {a}
    'a'::CHAR(1)           AS current_city,    ← СИМВОЛ a
    0                      AS accumulated_cost ← ЧИСЛО 0
```

| Колонка | Тип | Значение | Что хранит |
|---------|-----|----------|------------|
| visited_cities | varchar[] | {a} | Массив посещённых городов |
| current_city | CHAR(1) | a | Текущее местоположение |
| accumulated_cost | integer | 0 | Накопленная стоимость |
