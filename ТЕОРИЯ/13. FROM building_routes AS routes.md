## 📖 ПОШАГОВОЕ ОБЪЯСНЕНИЕ

### Структура:

```sql
WITH RECURSIVE building_routes AS (
    ╔═══════════════════════════════════════╗
    ║ ANCHOR MEMBER (база рекурсии)         ║
    ║ Не ссылается на building_routes       ║
    ╚═══════════════════════════════════════╝
    SELECT
        ARRAY['a']::varchar[] AS visited_cities,
        'a'::CHAR(1) AS current_city,
        0 AS accumulated_cost
    
    UNION ALL
    
    ╔═══════════════════════════════════════╗
    ║ RECURSIVE MEMBER (рекурсивный шаг)    ║
    ║ ТУТ ССЫЛАЕТСЯ НА СЕБЯ!                ║
    ╚═══════════════════════════════════════╝
    SELECT
        routes.visited_cities || ARRAY[edges.point2]::varchar[],
        edges.point2,
        routes.accumulated_cost + edges.cost
    FROM building_routes AS routes  ← ВОТ ЗДЕСЬ!
         ↑                  │
         └──────────────────┘
    JOIN tsp AS edges ...
)
```

## 🎬 КАК PostgreSQL ВЫПОЛНЯЕТ РЕКУРСИЮ

### ⚠️ НЕ ТАК (одновременно):

```
❌ НЕПРАВИЛЬНОЕ ПОНИМАНИЕ:

building_routes = anchor + recursive

Recursive читает из building_routes,
а building_routes одновременно создаётся...

→ Бесконечная рекурсия! Зацикливание!
```

### ✅ А ТАК (итеративно):

```
✅ ПРАВИЛЬНОЕ ПОНИМАНИЕ:

PostgreSQL выполняет ПОШАГОВО:

ШАГ 0: Выполняет anchor member
       → Создаёт ВРЕМЕННУЮ таблицу result₀
       result₀ = {a}

ШАГ 1: Выполняет recursive member
       FROM building_routes ← читает из result₀
       → Создаёт result₁
       result₁ = {a,b}, {a,c}, {a,d}

ШАГ 2: Выполняет recursive member
       FROM building_routes ← читает из result₁
       → Создаёт result₂
       result₂ = {a,b,c}, {a,b,d}, {a,c,b}, ...

ШАГ 3: Выполняет recursive member
       FROM building_routes ← читает из result₂
       → Создаёт result₃
       result₃ = {a,b,c,d}, {a,b,d,c}, ...

ШАГ 4: Выполняет recursive member
       FROM building_routes ← читает из result₃
       → result₄ = ∅ (пусто!)
       → СТОП! Рекурсия завершена.

ИТОГОВЫЙ building_routes = result₀ ∪ result₁ ∪ result₂ ∪ result₃
```

## 🎯 КЛЮЧЕВОЙ МОМЕНТ

### building_routes на каждой итерации = результат ПРЕДЫДУЩЕЙ итерации!

```
Итерация 0: building_routes не существует
            → Выполняется anchor
            → Создаётся building_routes₀

Итерация 1: FROM building_routes ← это building_routes₀
            → Создаётся building_routes₁

Итерация 2: FROM building_routes ← это building_routes₁
            → Создаётся building_routes₂

Итерация 3: FROM building_routes ← это building_routes₂
            → Создаётся building_routes₃

Итерация 4: FROM building_routes ← это building_routes₃
            → Результат пустой → СТОП
```

## 💡 АНАЛОГИЯ С РЕКУРСИЕЙ В ПРОГРАММИРОВАНИИ

### В C (классическая рекурсия):

```c
// Факториал (классическая рекурсия)
int factorial(int n) {
    if (n == 0) return 1;       // база рекурсии
    return n * factorial(n-1);   // рекурсивный вызов (ссылка на себя!)
                    ↑
                    └─── Функция вызывает САМУ СЕБЯ!
}

factorial(5)
  → 5 * factorial(4)
       → 4 * factorial(3)
            → 3 * factorial(2)
                 → 2 * factorial(1)
                      → 1 * factorial(0)
                           → 1 (база)
```

### В SQL (наш случай):

```sql
WITH RECURSIVE building_routes AS (
    -- База рекурсии
    SELECT ARRAY['a'] AS path
    
    UNION ALL
    
    -- Рекурсивный вызов
    SELECT routes.path || ...
    FROM building_routes AS routes  ← CTE ссылается на САМО СЕБЯ!
         ↑
         └─── Как функция вызывает саму себя!
)
```

## 🔄 СРАВНЕНИЕ: ФУНКЦИЯ vs CTE

| Аспект | Рекурсивная функция (C) | Рекурсивный CTE (SQL) |
|--------|-------------------------|----------------------|
| **База** | `if (n == 0) return 1` | Anchor member |
| **Рекурсия** | `factorial(n-1)` | `FROM building_routes` |
| **Самоссылка** | Функция вызывает себя | CTE читает из себя |
| **Остановка** | Условие `if` | WHERE не находит строк |
| **Результат** | Возвращает значение | Таблица из всех итераций |

## 🧪 УПРОЩЁННЫЙ ПРИМЕР

### Простая рекурсия - числа от 1 до 5:

```sql
WITH RECURSIVE numbers AS (
    -- База: начинаем с 1
    SELECT 1 AS n
    
    UNION ALL
    
    -- Рекурсия: добавляем n+1
    SELECT n + 1
    FROM numbers  ← ССЫЛАЕТСЯ НА САМО СЕБЯ!
    WHERE n < 5   ← Условие остановки
)
SELECT * FROM numbers;

-- Результат:
--  n
-- ---
--  1  ← итерация 0 (anchor)
--  2  ← итерация 1 (FROM numbers где n=1)
--  3  ← итерация 2 (FROM numbers где n=2)
--  4  ← итерация 3 (FROM numbers где n=3)
--  5  ← итерация 4 (FROM numbers где n=4)
```

### Как это работает:

```
Итерация 0: numbers = {1}
            (anchor member)

Итерация 1: FROM numbers (читает {1})
            SELECT 1+1 = 2
            numbers = {2}

Итерация 2: FROM numbers (читает {2})
            SELECT 2+1 = 3
            numbers = {3}

Итерация 3: FROM numbers (читает {3})
            SELECT 3+1 = 4
            numbers = {4}

Итерация 4: FROM numbers (читает {4})
            SELECT 4+1 = 5
            numbers = {5}

Итерация 5: FROM numbers (читает {5})
            WHERE 5 < 5 → FALSE
            numbers = ∅ (пусто)
            → СТОП!

UNION ALL всех итераций: {1,2,3,4,5}
```

## ⚠️ ПОЧЕМУ НЕТ БЕСКОНЕЧНОЙ РЕКУРСИИ?

### 3 механизма защиты:

#### 1️⃣ Условие в WHERE

```sql
WHERE NOT edges.point2 = ANY(routes.visited_cities)
          ↑
Когда все города посещены, условие FALSE
→ Не создаётся новых строк
→ Рекурсия останавливается
```

#### 2️⃣ PostgreSQL проверяет результаты

```sql
Если recursive member вернул 0 строк:
→ Рекурсия автоматически останавливается
```

#### 3️⃣ Внутренний лимит PostgreSQL

```sql
-- Есть встроенная защита от бесконечной рекурсии
-- По умолчанию: максимум ~1000 итераций

-- Можно изменить:
SET max_recursion_depth = 100;
```

## 🔍 ДЕТАЛЬНЫЙ ПРИМЕР ОДНОЙ ИТЕРАЦИИ

### Итерация 2:

```sql
-- ШАГ 1: PostgreSQL берёт result₁
FROM building_routes AS routes
     ↓
Читает из памяти:
┌──────────────────┬──────────────┐
│ visited_cities   │ current_city │
├──────────────────┼──────────────┤
│ {a,b}            │ b            │ ← строка 1
│ {a,c}            │ c            │ ← строка 2
│ {a,d}            │ d            │ ← строка 3
└──────────────────┴──────────────┘

-- ШАГ 2: Для каждой строки выполняет JOIN

Строка 1: {a,b}, current='b'
  JOIN tsp WHERE point1='b' AND point2 NOT IN {a,b}
  → Находит: b→c, b→d
  → Создаёт: {a,b,c}, {a,b,d}

Строка 2: {a,c}, current='c'
  JOIN tsp WHERE point1='c' AND point2 NOT IN {a,c}
  → Находит: c→b, c→d
  → Создаёт: {a,c,b}, {a,c,d}

Строка 3: {a,d}, current='d'
  JOIN tsp WHERE point1='d' AND point2 NOT IN {a,d}
  → Находит: d→b, d→c
  → Создаёт: {a,d,b}, {a,d,c}

-- ШАГ 3: Результат итерации 2
result₂ = {
  {a,b,c},
  {a,b,d},
  {a,c,b},
  {a,c,d},
  {a,d,b},
  {a,d,c}
}

-- ШАГ 4: Этот результат становится building_routes для итерации 3
```

## 💻 АНАЛОГИЯ В JavaScript

```javascript
// SQL рекурсивный CTE как итеративный процесс в JS:

function buildRoutes() {
    // Anchor member
    let current = [{path: ['a'], city: 'a', cost: 0}];
    let all = [...current];
    
    // Recursive member (итерации)
    while (current.length > 0) {
        let next = [];
        
        // FROM building_routes AS routes
        for (let route of current) {
            // JOIN tsp AS edges
            for (let edge of tsp.filter(e => e.point1 === route.city)) {
                // WHERE NOT ... = ANY(...)
                if (!route.path.includes(edge.point2)) {
                    next.push({
                        path: [...route.path, edge.point2],
                        city: edge.point2,
                        cost: route.cost + edge.cost
                    });
                }
            }
        }
        
        // Переходим к следующей итерации
        current = next;  // building_routes теперь = next
        all.push(...next);
    }
    
    return all;  // UNION ALL всех итераций
}
```

## ✅ ПРОВЕРЬ СЕБЯ

### Вопрос 1: Создаёт ли `FROM building_routes` рекурсию?

**Ответ:** ✅ ДА! Это и есть механизм рекурсии - CTE ссылается на само себя.

---

### Вопрос 2: Почему нет бесконечной рекурсии?

**Ответ:** Потому что WHERE фильтрует строки, и когда все города посещены, новых строк не создаётся → рекурсия останавливается.

---

### Вопрос 3: Что читает `FROM building_routes` на итерации 2?

**Ответ:** Результат итерации 1 (result₁).

---

### Вопрос 4: Это настоящая рекурсия или цикл?

**Ответ:** Технически это итеративный процесс (цикл), но в SQL называется "рекурсией" из-за самоссылки.

---

**ТЫ АБСОЛЮТНО ПРАВИЛЬНО ПОНЯЛ! Именно самоссылка `FROM building_routes` создаёт рекурсию!** 🎯

**Кратко:** `building_routes` ссылается на само себя через `FROM building_routes`, что создаёт рекурсивный процесс. PostgreSQL выполняет это итеративно: каждая итерация читает результат предыдущей, пока не будет создано 0 новых строк.
