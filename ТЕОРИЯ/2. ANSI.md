# 🏛️ ANSI/SPARC — Расшифровка и объяснение

## 📝 Расшифровка аббревиатур

### **ANSI**
**American National Standards Institute**  
**Американский национальный институт стандартов**

- 🇺🇸 Организация, которая создаёт стандарты в США
- 📐 Устанавливает правила для технологий, безопасности, качества
- 💻 В IT создала много стандартов (например, ANSI SQL)

**Аналогия:** Это как ГОСТ в России — организация, которая говорит "все должны делать вот так"

---

### **SPARC**
**Standards Planning And Requirements Committee**  
**Комитет планирования стандартов и требований**

- 👥 Группа экспертов внутри ANSI
- 📊 Специализируются на базах данных
- 📅 Создали архитектуру в **1975 году** (почти 50 лет назад!)

---

## 🏗️ ANSI/SPARC Architecture — Что это?

**Полное название:**  
**ANSI/SPARC Three-Level Architecture**  
**Трёхуровневая архитектура ANSI/SPARC**

Это **стандарт** того, как должны быть организованы базы данных.

---

## 📚 Три уровня (простыми словами)

### 🎨 **1. External Level (Внешний уровень)**
**Что видит пользователь**

```
Бухгалтер видит:
┌─────────────────────┐
│ Отчёт о продажах    │
│ Месяц: Январь       │
│ Сумма: 150,000₽     │
└─────────────────────┘

Программист видит:
SELECT sales FROM report WHERE month = 'January'
```

**Аналогия:** Это как витрина магазина — каждый покупатель видит только то, что ему интересно.

---

### 🧩 **2. Conceptual Level (Концептуальный уровень)**
**Логическая структура БД**

```sql
-- Все таблицы и связи:
person (id, name, age)
orders (id, person_id, date, amount)
pizzeria (id, name, rating)

-- Правила:
- person.id связан с orders.person_id
- amount не может быть отрицательным
```

**Аналогия:** Это как чертёж здания — показывает, где комнаты, как они связаны, но не как построены стены.

---

### 💾 **3. Internal Level (Внутренний уровень)**
**Физическое хранение**

```
- Файлы на диске: /var/lib/postgresql/data
- Индексы: B-tree для быстрого поиска
- Сжатие данных: GZIP
- Страницы памяти: 8KB блоки
```

**Аналогия:** Это как фундамент, проводка, трубы в стенах — пользователь не видит, но всё работает благодаря этому.

---

## 🎯 Зачем это нужно?

### Принцип: **Независимость данных (Data Independence)**

#### 📱 **Логическая независимость**
Можно менять концептуальный уровень, не ломая внешний.

**Пример:**
```sql
-- Было:
person (id, name, full_address)

-- Стало:
person (id, name)
address (person_id, city, street)
```

✅ Пользователи продолжают работать через VIEW — они ничего не заметили!

#### 💿 **Физическая независимость**
Можно менять хранение, не ломая логику.

**Пример:**
```
Было: HDD диск
Стало: SSD диск + другая файловая система
```

✅ SQL-запросы работают так же!

## 🍕 Аналогия с пиццерией

Представь, что ANSI/SPARC — это правила работы пиццерии:

### 🎨 **External Level (Меню для клиентов)**
```
Клиент видит:
🍕 Маргарита — 500₽
🍕 Пепперони — 700₽
```

Разные клиенты могут видеть разные меню:
- 👶 Детское меню
- 🌱 Вегетарианское меню
- 💰 VIP-меню со скидками

### 🧩 **Conceptual Level (Рецепты)**
```
Маргарита = тесто + томаты + моцарелла + базилик
Пепперони = тесто + томаты + моцарелла + пепперони

Правила:
- Пепперони должно быть >= 50г на пиццу
- Моцарелла хранится при +4°C
```

### 💾 **Internal Level (Склад и процессы)**
```
- Мука хранится в контейнере №5
- Томаты в холодильнике на полке №2
- Печь нагрета до 250°C
- Заказы обрабатываются через систему
```

---

## 📊 Как VIEW вписывается в ANSI/SPARC?

```
External Level:    VIEW (то, что видит пользователь)
        ↕
Conceptual Level:  TABLE (реальные таблицы)
        ↕
Internal Level:    FILES (файлы на диске)
```

**VIEW — это часть External Level!**

Они создают "персональный взгляд" на данные для каждого пользователя.

## 🎓 Историческая справка

**1975 год** — Комитет SPARC опубликовал эту архитектуру

**Почему это важно?**
- До этого каждая БД делала как хотела (хаос!)
- После этого появился единый стандарт
- Все современные БД (PostgreSQL, MySQL, Oracle) следуют этой модели

**Интересный факт:**  
Это было **за 10 лет до Windows 1.0** (1985) и **за 5 лет до появления SQL** (1980)! 🤯

## 🧠 Запомни:

> **ANSI/SPARC = правила игры для баз данных**
> 
> Как футбол: есть FIFA (ANSI), есть правила (SPARC), есть 3 части игры:
> - Зрители видят матч (External)
> - Судьи знают правила (Conceptual)
> - Работники стадиона готовят поле (Internal)

**VIEW** — это как **камеры для зрителей**: каждая показывает игру под своим углом! 📹
