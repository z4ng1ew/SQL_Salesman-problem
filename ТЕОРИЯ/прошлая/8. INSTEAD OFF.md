Для виртуальных таблиц можно создавать "INSTEAD OF" триггеры, что позволяет более гибко управлять входящими операциями изменения данных.



# 🔥 INSTEAD OF триггеры - объясняю ПРОСТО!

## 🎯 Сначала: Что такое ТРИГГЕР?

**ТРИГГЕР (trigger)** = автоматическое действие при событии

**Расшифровка слова:**
- **trigger** (английский) = "курок", "спусковой крючок"
- Нажал курок → выстрел
- Произошло событие → выполнилось действие

---

### 🎮 Аналогия с играми:

```javascript
// Это как обработчик события в JS:
button.addEventListener('click', function() {
    console.log('Кнопка нажата!');
});

// Нажал кнопку → автоматически выполнился код
```

**В БД:**
```sql
-- Триггер на таблицу:
CREATE TRIGGER my_trigger
AFTER INSERT ON person  -- после добавления в таблицу person
FOR EACH ROW
EXECUTE FUNCTION log_insert();  -- выполни функцию

-- Добавил строку → автоматически выполнилась функция!
```

## ❌ Проблема: VIEW нельзя изменять!

### Вспомни: VIEW = окно

```
        ┌───────┐
        │ ОКНО  │ ← VIEW
        │(VIEW) │
        └───┬───┘
            │ (просто смотрит)
            ↓
┌─────────────────────┐
│   КОМНАТА (таблица) │
│  📦 Коробка 1       │
│  📦 Коробка 2       │
└─────────────────────┘
```

**Попробуем добавить данные в VIEW:**

```sql
-- VIEW показывает взрослых:
CREATE VIEW v_adults AS
SELECT name, age FROM person WHERE age >= 25;

-- Попытка добавить через VIEW:
INSERT INTO v_adults VALUES ('Петя', 30);
```

💥 **ОШИБКА!**

```
ERROR: cannot insert into view "v_adults"
HINT: You need an INSTEAD OF INSERT trigger
```

**Почему?** Потому что:
- VIEW - это не коробка, а окно!
- Ты пытаешься положить вещь В ОКНО
- Но в окно ничего не положишь!

---

### 🤔 "Но погоди! Почему нельзя автоматически?"

PostgreSQL думает:

```
VIEW v_adults = SELECT * FROM person WHERE age >= 25

Хочешь добавить ('Петя', 30)?
Но куда именно добавить?
- В таблицу person? (а там есть другие колонки: id, gender, address!)
- А что с этими колонками делать?
- А если age < 25, добавлять или нет?

Я не знаю! 🤷
```

---

## ✅ Решение: INSTEAD OF триггер

**INSTEAD OF** = "ВМЕСТО ЭТОГО"

**Расшифровка:**
- **instead** = вместо
- **of** = (чего-то)
- **INSTEAD OF** = вместо этой операции

---

### 📝 Как это работает?

```
ОБЫЧНО (без триггера):
Ты: INSERT INTO v_adults ...
PostgreSQL: ❌ "Не могу! Это VIEW!"

С INSTEAD OF триггером:
Ты: INSERT INTO v_adults ...
PostgreSQL: "Окей, ВМЕСТО добавления в VIEW
            выполню ТВОЮ функцию!"
      ↓
Выполняется ТВОЯ функция
      ↓
Функция делает, что ты скажешь
```

---

## 🔧 Конкретный пример

### Задача: Хотим добавлять людей через VIEW

```sql
-- VIEW показывает только взрослых:
CREATE VIEW v_adults AS
SELECT id, name, age FROM person WHERE age >= 25;
```

---

### Шаг 1: Создаём функцию (что делать ВМЕСТО)

```sql
CREATE OR REPLACE FUNCTION insert_adult()
RETURNS TRIGGER AS $$
BEGIN
    -- NEW.name и NEW.age - это то, что пытается добавить пользователь
    
    -- Проверка: возраст должен быть >= 25
    IF NEW.age < 25 THEN
        RAISE EXCEPTION 'Возраст должен быть >= 25!';
    END IF;
    
    -- Добавляем в РЕАЛЬНУЮ таблицу person:
    INSERT INTO person (id, name, age, gender, address)
    VALUES (
        nextval('person_id_seq'),  -- генерируем id
        NEW.name,                  -- имя от пользователя
        NEW.age,                   -- возраст от пользователя
        'unknown',                 -- пол по умолчанию
        'unknown'                  -- адрес по умолчанию
    );
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**На простом языке:**
```
Функция говорит:
"Когда кто-то пытается добавить в VIEW,
я проверю возраст,
и если всё ок - добавлю в НАСТОЯЩУЮ таблицу person"
```

---

### Шаг 2: Создаём триггер INSTEAD OF

```sql
CREATE TRIGGER instead_of_insert_adults
INSTEAD OF INSERT ON v_adults  -- ВМЕСТО вставки в VIEW
FOR EACH ROW                    -- для каждой строки
EXECUTE FUNCTION insert_adult();  -- выполни мою функцию
```

**На простом языке:**
```
"Эй, PostgreSQL!
Когда кто-то пытается INSERT в v_adults,
не делай это напрямую,
а вместо этого (INSTEAD OF) вызови мою функцию!"
```

---

### Шаг 3: Теперь можно добавлять через VIEW!

```sql
-- Теперь это работает!
INSERT INTO v_adults (name, age) VALUES ('Петя', 30);
```

**Что происходит внутри:**

```
1. Пользователь: INSERT INTO v_adults ...
         ↓
2. PostgreSQL: "Это VIEW с INSTEAD OF триггером!"
         ↓
3. PostgreSQL: "Вызываю функцию insert_adult()"
         ↓
4. Функция:
   - Проверяет: age >= 25? ✅ Да
   - Добавляет в person с дефолтными значениями
         ↓
5. Успех! ✅
```

## 🎭 Аналогия со ШВЕЙЦАРОМ

### Без INSTEAD OF (швейцара нет):

```
Ты идёшь к окну (VIEW)
Пытаешься просунуть коробку в окно
💥 Не получается! Окно закрыто!
```

---

### С INSTEAD OF (есть швейцар):

```
Ты идёшь к окну (VIEW)
Отдаёшь коробку швейцару (триггер)
   ↓
Швейцар (функция):
   ✅ Проверяет коробку (age >= 25?)
   ✅ Открывает дверь
   ✅ Заносит коробку В КОМНАТУ (в таблицу)
   ✅ Кладёт на нужное место
```

**INSTEAD OF = инструкция для швейцара, что делать ВМЕСТО прямой вставки**

## 🔥 Ещё примеры операций

### UPDATE (изменение):

```sql
-- Триггер для UPDATE:
CREATE TRIGGER instead_of_update_adults
INSTEAD OF UPDATE ON v_adults
FOR EACH ROW
EXECUTE FUNCTION update_adult();

-- Функция:
CREATE OR REPLACE FUNCTION update_adult()
RETURNS TRIGGER AS $$
BEGIN
    -- OLD - старое значение, NEW - новое значение
    
    UPDATE person
    SET name = NEW.name,
        age = NEW.age
    WHERE id = OLD.id;
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Теперь можно:**
```sql
UPDATE v_adults SET age = 35 WHERE name = 'Петя';
-- Сработает триггер → обновит в настоящей таблице!
```

---

### DELETE (удаление):

```sql
CREATE TRIGGER instead_of_delete_adults
INSTEAD OF DELETE ON v_adults
FOR EACH ROW
EXECUTE FUNCTION delete_adult();

-- Функция:
CREATE OR REPLACE FUNCTION delete_adult()
RETURNS TRIGGER AS $$
BEGIN
    -- OLD - удаляемая строка
    
    DELETE FROM person WHERE id = OLD.id;
    
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;
```

**Теперь можно:**
```sql
DELETE FROM v_adults WHERE name = 'Петя';
-- Сработает триггер → удалит из настоящей таблицы!
```

## 🎯 "Гибко управлять входящими операциями"

### Что значит "гибко"?

В функции триггера ты можешь:

#### 1️⃣ **Проверять данные:**

```sql
IF NEW.age < 18 THEN
    RAISE EXCEPTION 'Нельзя добавлять детей!';
END IF;
```

#### 2️⃣ **Преобразовывать данные:**

```sql
-- Автоматически делать имя в верхнем регистре:
NEW.name := UPPER(NEW.name);
```

#### 3️⃣ **Добавлять дополнительные данные:**

```sql
-- Автоматически добавить время создания:
INSERT INTO person (name, age, created_at)
VALUES (NEW.name, NEW.age, NOW());
```

#### 4️⃣ **Логировать действия:**

```sql
-- Записать в лог:
INSERT INTO audit_log (action, user, time)
VALUES ('INSERT', current_user, NOW());
```

#### 5️⃣ **Распределять по таблицам:**

```sql
IF NEW.age >= 18 THEN
    INSERT INTO adults (name, age) VALUES (NEW.name, NEW.age);
ELSE
    INSERT INTO children (name, age) VALUES (NEW.name, NEW.age);
END IF;
```

## 🔄 Сравнение с обычными триггерами

| Тип | Когда срабатывает | Где используется |
|-----|------------------|------------------|
| **AFTER** | ПОСЛЕ операции | На таблицах |
| **BEFORE** | ПЕРЕД операцией | На таблицах |
| **INSTEAD OF** | ВМЕСТО операции | На VIEW! |

---

### AFTER триггер (на таблице):

```sql
CREATE TRIGGER after_insert
AFTER INSERT ON person  -- после вставки В ТАБЛИЦУ
FOR EACH ROW
EXECUTE FUNCTION log_action();

-- Операция:
1. INSERT выполнится
2. Данные добавятся в таблицу
3. ПОТОМ выполнится функция
```

---

### INSTEAD OF триггер (на VIEW):

```sql
CREATE TRIGGER instead_of_insert
INSTEAD OF INSERT ON v_adults  -- вместо вставки В VIEW
FOR EACH ROW
EXECUTE FUNCTION my_custom_insert();

-- Операция:
1. INSERT НЕ выполнится напрямую
2. ВМЕСТО этого выполнится твоя функция
3. Функция сама решает, что делать
```

## 🧠 Аналогия с программированием (JS/C)

### В JavaScript:

```javascript
// Обычная операция:
array.push(item);  // просто добавляет

// С "INSTEAD OF" (через Proxy):
const arrayProxy = new Proxy(array, {
    set(target, property, value) {
        // ВМЕСТО прямого добавления:
        console.log('Перехватили добавление!');
        
        // Моя логика:
        if (value.age >= 25) {
            target[property] = value;  // добавляем только взрослых
        } else {
            throw new Error('Только взрослые!');
        }
        
        return true;
    }
});

// Теперь:
arrayProxy.push({name: 'Петя', age: 30});  // ✅ ОК
arrayProxy.push({name: 'Вася', age: 15});  // ❌ Ошибка!
```

---

### В C (аналогия):

```c
// Обычная функция:
void add_person(Person* p) {
    // Прямо добавляет
    database_insert(p);
}

// С "INSTEAD OF" логикой:
void add_person_via_view(Person* p) {
    // ВМЕСТО прямого добавления:
    
    // 1. Проверка:
    if (p->age < 25) {
        fprintf(stderr, "Ошибка: только взрослые!\n");
        return;
    }
    
    // 2. Дополнительная логика:
    p->created_at = time(NULL);
    
    // 3. Логирование:
    log_action("INSERT", p->name);
    
    // 4. Только теперь добавление:
    database_insert(p);
}
```

## 💡 Зачем это нужно в реальной жизни?

### Пример 1: Безопасность

```sql
-- VIEW показывает только нужные колонки:
CREATE VIEW v_user_public AS
SELECT id, name, age FROM users;  -- БЕЗ пароля и email!

-- INSTEAD OF триггер проверяет права:
CREATE FUNCTION insert_user_public()
RETURNS TRIGGER AS $$
BEGIN
    -- Проверить, есть ли права:
    IF NOT has_permission(current_user, 'add_users') THEN
        RAISE EXCEPTION 'Нет прав!';
    END IF;
    
    -- Добавить с дефолтным паролем:
    INSERT INTO users (name, age, password)
    VALUES (NEW.name, NEW.age, 'default123');
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

---

### Пример 2: Упрощение для пользователя

```sql
-- Сложная таблица:
-- person: id, first_name, last_name, birth_date, created_at, updated_at

-- Простой VIEW:
CREATE VIEW v_person_simple AS
SELECT id, first_name || ' ' || last_name AS full_name
FROM person;

-- INSTEAD OF INSERT - сам разбивает имя:
CREATE FUNCTION insert_person_simple()
RETURNS TRIGGER AS $$
BEGIN
    -- Пользователь даёт "Иван Петров"
    -- Триггер разбивает на first_name и last_name
    
    INSERT INTO person (first_name, last_name, created_at)
    VALUES (
        split_part(NEW.full_name, ' ', 1),  -- "Иван"
        split_part(NEW.full_name, ' ', 2),  -- "Петров"
        NOW()
    );
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Пользователь просто пишет:**
```sql
INSERT INTO v_person_simple (full_name) VALUES ('Иван Петров');
-- Триггер сам разберётся!
```

## 📊 Итоговая схема

```
БЕЗ INSTEAD OF:
Пользователь → INSERT INTO view → ❌ ОШИБКА

С INSTEAD OF:
Пользователь → INSERT INTO view
      ↓
INSTEAD OF триггер перехватывает
      ↓
Выполняется твоя функция:
  - Проверки ✅
  - Преобразования ✅
  - Логирование ✅
  - Распределение по таблицам ✅
      ↓
INSERT в реальную таблицу
      ↓
✅ Успех!
```

## 🧠 Резюме

| Понятие | Простыми словами |
|---------|------------------|
| **Триггер** | Автоматическое действие при событии |
| **INSTEAD OF** | "Вместо этого сделай вот что" |
| **Для VIEW** | Позволяет изменять VIEW (через твою логику) |
| **Гибко управлять** | Можешь добавить проверки, преобразования, логи |

---

## 📌 Запомни:

> **INSTEAD OF триггер = ШВЕЙЦАР для VIEW**
>
> - Ты не можешь в окно положить вещь
> - Но можешь отдать швейцару
> - Швейцар (триггер) сам занесёт в комнату (таблицу)
> - И сделает всё, что ты ему скажешь!

### На JS:

```javascript
// VIEW = read-only объект
const view = { name: 'Anna', age: 25 };

// INSTEAD OF = Proxy, который перехватывает операции
const viewWithTrigger = new Proxy(view, {
    set(target, key, value) {
        console.log('INSTEAD OF: делаю свою логику!');
        // Твоя логика здесь
        return true;
    }
});
```

**INSTEAD OF = способ сделать VIEW изменяемым через ТВОЮ логику!** 🎯
